Three status colours, **success**, **warning** and **error**, for results: lint findings, a failed build, checks, counts. They always come with a marker shape and a word, never alone.

## The tokens

| Token               | For                                                                                      |
| ------------------- | ---------------------------------------------------------------------------------------- |
| `status-<s>-text`   | Words and counts. 7:1 on `bg-canvas`, `bg-surface`, `bg-subtle` and its own subtle tint. |
| `status-<s>-marker` | Marker shapes and banner outlines. 3:1 on the same grounds. Never for text.              |
| `status-<s>-subtle` | The tint of a status chip or banner; text on it uses that status's `text`.               |

Primitives: `sage` (success), `ochre` (warning), `crimson` (error). A test checks every pair in both themes; a browser test checks the rendered pages.

## When to use which

| Status      | Means                                     | Marker        | Examples                                       |
| ----------- | ----------------------------------------- | ------------- | ---------------------------------------------- |
| **success** | It ran and nothing is wrong.              | dot           | `dta lint` passed, a passing `dta diff` report |
| **warning** | Deserves a look; nothing is blocked.      | open ring     | lint warnings, "passed with warnings"          |
| **error**   | Broken; stops the work until it is fixed. | filled square | lint errors, "build failed", unreadable input  |

Not a status:

- **Changed is `signal`**, never a status. A change is not a problem, and a problem is never orange.
- **Information and selection are `action`.**
- **Pending is the ink.**
- **Examples never use system colours** ([below](#examples-stay-blue-and-grey)).

## Shape, word and colour

- **Shape:** filled square (error), open ring (warning), dot (success), the same in every component.
- **Word:** the CLI's words ("error", "warn", "passed", "3 errors") in `status-*-text`; the rest of the line stays in the ink.
- **Colour:** marker in `status-*-marker`, word in `status-*-text`.

## The status banner

For what stops the work (unreadable input, a failed build): the status's subtle tint inside a complete 2 px outline (`stroke-ink`) in its marker colour, `radius-md`, every line in its status text. It is [Findings](/design-system/components/findings/) with `banner`. Not for a lint view, a hint, or a change.

## Selection and status

A selected finding shows both: the `action-subtle` tint with the line in `action-text`, the marker and word in their status colours. Its file turns `action-text` too (`fg-subtle` is too weak on the tint).

## Changes to review

"Changes to review" is a diff to look at: `signal` everywhere, never a warning or the action tint.

- **In [Checks](/design-system/components/checks/):** dot in `signal-bg`, words in `signal-text`, on `bg-surface`.
- **In the `dta diff` report:** the [Chip](/design-system/components/chip/)'s `changed` look: `signal-subtle` tint, word and dot in `signal-text` (`signal-bg` is too weak on the tint).

## Examples stay blue and grey

Example content (fixtures, sample tokens, example UI in stories, the report's example data) uses blues and neutral greys only, never `signal` or a status colour or a hue near them: it would read as a change or a result. Exceptions: the gravity well's orange objects (decoration) and the report's pixel-diff overlay. `site/example-colours.test.ts` fails on orange, red, yellow or green in example colours.

## Do and don't

| Do                                                                  | Don't                                                        |
| ------------------------------------------------------------------- | ------------------------------------------------------------ |
| Pair every status colour with its shape and a word.                 | Tell a status by colour alone.                               |
| Use `status-error-*` for errors and failures.                       | Use `signal` for an error or a warning.                      |
| Keep examples blue or grey.                                         | Give an example orange, red, yellow or green.                |
| Keep "changes to review" in `signal`.                               | Turn a change into a warning, or show it in the action tint. |
| Text in `status-*-text`; markers and outlines in `status-*-marker`. | Write text in a marker colour (only 3:1).                    |
| A banner with a complete 2 px outline on the subtle tint.           | A coloured bar on one side of a rounded box.                 |
