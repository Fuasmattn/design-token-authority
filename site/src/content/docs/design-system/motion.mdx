Motion has one job here: that a change is seen. Without it people miss what changed (change blindness).

## The rule

**Every state change a person should notice is transitioned, never instant.**

- **Things come from where they come from**, and leave back there: the side panel from the right, the bottom sheet from the bottom, the input collapses into the source bar, new results fade in one after another (`motion.stagger`).
- **Content that changes in place crossfades**: a tab's panel, a rebuilt group of files.
- **A changed value is briefly highlighted** in `action-subtle` with `action-text`, over `motion.duration.highlight`. Use [Changed](/design-system/components/changed/).
- **Layout animates instead of jumping**: columns narrow, disclosures grow, items below move up.
- **Short:** `fast` for small changes in place, `base` for most, `slow` (320 ms) for larger moves. No bounce, no overshoot, no decoration; only the landing page's [gravity well](/design-system/components/gravity-well/) and [floating objects](/design-system/components/floating-objects/) move for their own sake.
- **Selection** tints and the tab indicator transition too, but selection is never shown by motion alone.

## Reduced motion

Under `prefers-reduced-motion: reduce`, nothing moves and changes are instant (no View Transitions). **The highlight of a changed value stays**: it is information, only its colours change. End-to-end tests check both.

## Do and don't

| Do                                                                              | Don't                                                                 |
| ------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Slide the sheet up, and down again on close.                                    | Let a panel or sheet appear or vanish in one frame.                   |
| Crossfade a tab's panel and move the indicator.                                 | Swap content under a tab without a transition.                        |
| Highlight a changed count with Changed.                                         | Change a number silently, or flash it in `signal`.                    |
| Animate a disclosure's height in CSS (`::details-content`, `interpolate-size`). | Measure heights in script, or let content jump.                       |
| Use `var(--motion-duration-*)` and `var(--motion-ease-*)`.                      | Write `0.2s ease` or `cubic-bezier(…)` in a component (a test fails). |
| Turn movement off under reduced motion, keep the highlight.                     | Turn the highlight off too.                                           |
| Change a hover at once; transition state changes.                               | Transition a hover on a property a state also changes.                |

## How it is built

- **CSS transitions** on the tokens in each component; the [Detail panel](/design-system/components/detail-panel/) uses `@starting-style` so a native `<dialog>` slides in and out.
- **View Transitions** through `transition(update, type)` in `src/components/ds/motion.ts`; they fall back to an instant change without the API or under reduced motion. Elements sharing a `view-transition-name` move to their new place (`dta-source`: input to source bar).
- **Highlight:** `useChanged` in `motion.ts` with the [Changed](/design-system/components/changed/) component; the first render is never highlighted.
- Layout shift stays 0 (tests measure it).
