The facts of what is loaded in one line above the [playground](/playground/)'s views: collections, brands, breakpoints, tokens, lint findings, output files. Each part with a view behind it opens that view.

## When to use

- Above [Tabs](/design-system/components/tabs/) whose views each explain one of the numbers.
- Not for prose or for numbers without a view.

<Examples component="summary-line" />

## Guidelines

- Mono `meta` in `fg-muted`; parts that open a view are `fg-default` with a hairline `border-strong` underline that thickens on hover. Spaced with `space-6`, no separators.
- **Status counts** (`tone`): the lint count and a failed build show their [status](/design-system/status-colours/) marker and words in `status-*-text` (`1 error, 2 warnings`, `0 lint findings`, `build failed`). Other counts stay plain.
- Counts in the CLI's words, with plurals (`1 collection`). Until the outputs are built, that part reads `build outputs`, then `11 output files`.
- **Reading** (`reading`): while input waits, one muted part says `Reading 6 files…` as a polite status (list `aria-busy`), as tall as a button part so nothing moves. No spinner. If the analysis fails to load: `The analysis did not load. Reload the page to try again.` in the error tone.
- Wraps on narrow screens, never scrolls sideways; buttons at least 24 px tall.
- A named list ("Summary"); a button opens its tab and moves focus there.
- **Motion:** a part whose text changes lights up ([Changed](/design-system/components/changed/)), also under reduced motion; view-transition part `dta-summary`.
