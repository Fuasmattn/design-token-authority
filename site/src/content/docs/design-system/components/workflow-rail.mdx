The workflow at a glance, on the landing page under "How it works": a change is made on one side (Figma, a token file, an agent), crosses into the repository and runs through the pull request's steps.

<Examples component="workflow-rail" />

## Guidelines

- **Two sides, one crossing:** the change side under a dashed `rail` bracket, its command (`dta pull`) on the crossing, the pull request under a solid `border-strong` bracket with its steps and thin `fg-subtle` arrows.
- **Each step:** a one-word label, one short line in `fg-muted`, its command as a [Command button](/design-system/components/command-button/). A step without a command (the person deciding) gets none.
- **No arrow back:** a return line says where a fix goes and may carry a command (`dta audit`). Not a loop, not numbered; an ordered list for screen readers, with a visually hidden heading.
- **Layout:** one row from 960 px of container; below that a vertical list where the brackets become left rules (solid for the pull request, dashed for the change).
- Rules and type only: no card, shadow, grid paper or motion. Text pairs 7:1 in both themes.
