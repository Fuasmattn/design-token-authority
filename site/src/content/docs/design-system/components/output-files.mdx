The files `dta build` writes, grouped by kind (CSS, Tailwind, JS), each with its size, Copy and Download, and one zip per group; used in the [playground](/playground/)'s Outputs view.

## When to use

- For a handful to a few dozen generated files a visitor takes some or all of.
- Not for source files someone edits, and not for a single file (show that in the panel or a Terminal).

## Guidelines

- Rules and type on the canvas, no cards. Group head: name in `title` type, file count in mono `fg-muted`, the group download as an outline Button, closed by a `stroke-ink` rule in `border-strong`.
- One row per file, hairlines between: the path in mono `action-text`, underlined (it opens the preview in the [Detail panel](/design-system/components/detail-panel/)); the size in mono `fg-muted`; Copy ([Copy button](/design-system/components/copy-button/)) and Download as quiet Buttons, at least 44 px. Accessible names say which file (`Download output/css/base.css`).
- A group that mixes outputs (Tailwind v4 and v3) labels each row with its output as a hairline tag; groups with one output don't.
- The row whose preview is open has `aria-current` and the `action-subtle` tint.
- Below 560 px the path takes its own line, size and actions under it; nothing scrolls sideways. Paths break after `/` or `.` ([Token path](/design-system/components/token-path/)).
- **When the build fails** there are no files: show the diagnostics as an error status banner ([Findings](/design-system/components/findings/) with `banner`).
- The component reports clicks; saving files is the page's job.
- **Motion:** groups are view-transition parts (`dta-swap`) when the formats change; the open row's tint over `fast` ([Motion](/design-system/motion/)).
