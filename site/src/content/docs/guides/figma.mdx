How DTA reads your Figma variables depends on your plan. `dta init` asks and sets it up.

| Plan                       | Pull                            | Push          |
| -------------------------- | ------------------------------- | ------------- |
| Enterprise                 | `dta pull` (REST API)           | `dta push`    |
| Professional, Organization | `dta pull --from-file <export>` | not available |

## Enterprise: the REST API

```sh
npx dta pull
```

Reads the variables of one Figma file into `tokens/`. It needs two values in `.env` in the folder you run it in (never commit it); `dta init` writes them:

```text title=".env"
FIGMA_FILE_KEY=…
FIGMA_PERSONAL_ACCESS_TOKEN=…
```

The file key is in the file's URL (`figma.com/file/<FILE_KEY>/…`); the token comes from Figma › Settings › Personal access tokens.

## Any plan: a plugin export

Export your variables with a Figma plugin (tokenHaus, for example), then:

```sh
npx dta pull --from-file export.json
```

DTA reads its own format ([Token files](/reference/token-files/)) and converts a few known plugin exports. Another plugin? Convert its output to the documented format, or [contribute an adapter](/contribute/).

:::tip[Default mode names]
`dta lint` fails on Figma's default mode name `Mode 1`: rename modes to what they mean (`Light`, `BrandA`, `Desktop`).
:::

## Pushing back to Figma

```sh
npx dta push --dry-run
```

Shows what `dta push` would change (Enterprise only). Without `--dry-run` it runs `dta lint` first, then asks you to type `push variables to figma`; `--yes` (or `push.skipConfirmation`) skips that in CI. It creates and updates variables and **never deletes** one.

Figma variables hold colours, numbers, text and booleans. Tokens Figma can't hold (`rem` sizes, font weights, shadows and other composite types) are skipped with a warning that says why. A colour outside sRGB is clipped, with a `clipped-to-srgb` warning.

### Removing variables: dta prune

```sh
npx dta prune --dry-run
```

Lists Figma variables whose token is gone. Without `--dry-run` it asks you to type `delete variables from figma` (`--force` skips that, in CI). It is careful on purpose:

- only collections that are in your token files are looked at;
- a collection that would lose more than half its variables is left alone (`--allow-bulk` overrides);
- a variable that others still alias is kept: run `dta push` first.

Figma's API can't say which layers use a variable, so check the list before you confirm.
