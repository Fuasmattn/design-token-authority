Use your tokens as Tailwind utilities. `dta build` writes the Tailwind files next to the CSS:

| File                                         | For                                           |
| -------------------------------------------- | --------------------------------------------- |
| `output/tailwind/tailwind.css`               | Tailwind v4: `@theme` with `var()` references |
| `output/tailwind/<brand>/tailwind.css`       | Tailwind v4: one brand, resolved values       |
| `output/tailwind/tailwind.tokens.ts`         | Tailwind v3: a `theme.extend` object          |
| `output/tailwind/<brand>/tailwind.tokens.ts` | Tailwind v3: one brand, resolved              |

## Tailwind v4

Import the token CSS, then the `@theme` file. Map brand tokens with `@theme inline` so they switch with `[data-brand]`:

```css title="src/app.css"
@import 'tailwindcss';
@import '../output/css/variables.css';
@import '../output/css/themes/branda.css';
@import '../output/css/themes/brandb.css';
@import '../output/tailwind/tailwind.css';

@theme inline {
  --color-brand-primary: var(--colors-brand-primary);
  --color-brand-accent: var(--colors-brand-accent);
}
```

```html
<html data-brand="branda">
  <button class="bg-brand-primary p-4">Save</button>
</html>
```

- **Your spacing replaces Tailwind's scale:** a spacing token `…spacing.4` becomes `--spacing-4`, so `p-4` uses it.
- **Breakpoint tokens switch** with the screen when `breakpoints` is set ([Breakpoint modes](/reference/outputs/#breakpoint-modes)); keep `variables.css` loaded.
- **Ship one brand only?** Use `output/tailwind/<brand>/tailwind.css` instead.

## Tailwind v3

```ts title="tailwind.config.ts"
import type { Config } from 'tailwindcss'
import { tokens } from './output/tailwind/tailwind.tokens'

export default {
  content: ['./src/**/*.{html,tsx}'],
  ...tokens,
} satisfies Config
```

The values are `var()` references, so load `output/css/variables.css` in your app.
