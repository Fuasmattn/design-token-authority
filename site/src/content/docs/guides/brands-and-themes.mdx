A brand (or a theme) is a **mode** of the collection that holds your semantic tokens. In the `brand-ab` fixture that collection is `Brand(Alias)` with the modes `BrandA` and `BrandB`; both alias into the same primitives:

```json title="tokens/Brand(Alias).BrandA.json (excerpt)"
{
  "Colors": {
    "Brand": { "Primary": { "$type": "color", "$value": "{Colors.Foundation.Blue.500}" } }
  }
}
```

```json title="tokens/Brand(Alias).BrandB.json (excerpt)"
{
  "Colors": {
    "Brand": { "Primary": { "$type": "color", "$value": "{Colors.Foundation.Navy.500}" } }
  }
}
```

## Build one theme per brand

List the modes to build in `brands`:

```ts title="dta.config.ts"
export default {
  brands: ['BrandA', 'BrandB'],
  // …
}
```

`dta build` then writes the primitives once (`output/css/variables.css`, on `:root`) and one file per brand, scoped to an attribute with the lower-cased brand name:

```css title="output/css/themes/brandb.css (excerpt)"
[data-brand="brandb"] {
  --colors-brand-primary: var(--colors-foundation-navy-500);
  …
}
```

Load all of them and switch with the attribute. It works on any element, so a page can show two brands side by side:

```html
<link rel="stylesheet" href="output/css/variables.css" />
<link rel="stylesheet" href="output/css/themes/branda.css" />
<link rel="stylesheet" href="output/css/themes/brandb.css" />

<html data-brand="branda">
  …
  <section data-brand="brandb">this part uses BrandB</section>
</html>
```

Because brand values stay `var()` references to the primitives, a change to `Colors.Foundation.Blue.500` reaches every brand that uses it without a rebuild of the themes.

### Tokens that alias brand tokens

A collection with one mode (a component tier, say) is written to `variables.css` on `:root`. When one of its tokens aliases a brand token, directly or through other single-mode tokens, each theme file declares it again with the same reference. CSS resolves `var()` where a property is declared, so the copy in the theme is what lets a nested `data-brand` section resolve it to its own brand. A build of the Learn `multi-brand` example with a single-mode `Component` collection added (`button.background` → `{action.background}`, `button.radius` → `{shape.control}`, `card.accent` → `{button.background}`, `button.border` → `{color.blue.600}`):

{/* prettier-ignore */}
```css title="output/css/themes/brandb.css"
[data-brand="brandb"] {
  --action-background: var(--color-green-600);
  --action-foreground: var(--color-neutral-0);
  --shape-control: var(--radius-999);
  --type-heading: var(--font-serif);
  --button-background: var(--action-background);
  --button-radius: var(--shape-control);
  --card-accent: var(--button-background);
}
```

All four are in `variables.css` on `:root` as before; `--button-border` aliases a primitive only, so it is not repeated in the themes. What `base.css` writes for them: [Outputs](/reference/outputs/#single-mode-tokens-that-alias-brand-tokens).

### Breakpoint tokens and brands

The same holds for a [breakpoint collection](/reference/outputs/#breakpoint-modes): a breakpoint token that aliases a brand token in any of its modes is repeated in every theme, once per mode, inside the same media queries. The Learn `multi-brand` example with a `Screen` collection added (`card.radius` → `{radius.4}` on Mobile, `{radius.999}` on Desktop; `card.accent` → `{color.blue.600}` on Mobile, `{action.background}` on Desktop) and `breakpoints: { collection: 'Screen', default: 'Mobile', modes: { Desktop: '(min-width: 1024px)' } }`:

{/* prettier-ignore */}
```css title="output/css/themes/brandb.css"
[data-brand="brandb"] {
  --action-background: var(--color-green-600);
  --action-foreground: var(--color-neutral-0);
  --shape-control: var(--radius-999);
  --type-heading: var(--font-serif);
}

/* Screen · Mobile (default) */
[data-brand="brandb"] {
  --card-accent: var(--color-blue-600);
}

/* Screen · Desktop */
@media (min-width: 1024px) {
  [data-brand="brandb"] {
    --card-accent: var(--action-background);
  }
}
```

So a `<section data-brand="brandb">` inside a BrandA page gets BrandB's green accent from 1024 px and the blue one below. `card.radius` reaches primitives only and stays in `variables.css`.

## Light and dark

Light and dark are the same mechanism: a collection with the modes `Light` and `Dark` (or `Graphite`), listed in `brands`. This website does exactly that: its tokens have a `Theme` collection with `Light` and `Graphite`, built into `[data-brand="light"]` and `[data-brand="graphite"]`, and a small script sets the attribute when you switch the theme.

:::note[Brands and themes together]
DTA treats every mode listed in `brands` as one theme file. A set with both brands and light/dark (BrandA light, BrandA dark, …) needs one mode per combination for now; combining independent dimensions (brand × theme × breakpoint) is planned.
:::

## Keep the brand layer clean

The `semantic-must-alias` rule fails when a token in the brand layer holds a raw value instead of an alias, so a brand never drifts from the palette:

```ts
lint: { rules: { 'semantic-must-alias': { severity: 'error', collections: ['Brand(Alias)'] } } }
```

`color-contrast` checks text and background pairs through their aliases, once per brand (and per light or dark mode, if you have them); a finding names the brand it fails in: [Lint rules](/reference/lint-rules/).
