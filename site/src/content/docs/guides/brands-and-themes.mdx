How to build several brands (or light and dark) from one token set. A brand is a **mode** of the collection that holds your semantic tokens: `Brand.BrandA.json`, `Brand.BrandB.json`.

## Build one theme per brand

List the modes in `brands`:

```ts title="dta.config.ts"
brands: ['BrandA', 'BrandB'],
```

`dta build` writes the primitives once (`variables.css`) and one theme per brand, scoped to `[data-brand="<brand>"]`:

{/* prettier-ignore */}
```css title="output/css/themes/brandb.css"
[data-brand="brandb"] {
  --colors-brand-primary: var(--colors-foundation-navy-500);
}
```

Load all of them and switch with the attribute, on any element:

```html
<html data-brand="branda">
  <section data-brand="brandb">this part uses BrandB</section>
</html>
```

### Tokens that alias brand tokens

A single-mode token that aliases a brand token (a `button.background` pointing at `{action.background}`) is declared again in every theme, so a nested `data-brand` section resolves it to its own brand. Nothing to configure. What `base.css` writes for them: [Outputs](/reference/outputs/#single-mode-tokens-that-alias-brand-tokens).

### Breakpoint tokens and brands

The same holds for a [breakpoint collection](/reference/outputs/#breakpoint-modes): a breakpoint token that aliases a brand token is repeated in every theme, inside the same media queries.

## Light and dark

The same mechanism: a collection with the modes `Light` and `Dark`, listed in `brands`, switched with `data-brand`. This website works that way.

## Brands and themes together

For brands _and_ light and dark at once, describe them as two **modifiers** in a DTCG [resolver document](/reference/token-files/#resolver-documents) instead of one mode per combination. `dta build` combines them:

```html
<html data-theme="light" data-brand="a">
  <section data-theme="dark">dark × a</section>
</html>
```

`brands` names the modifier that switches with `data-brand`; the other one switches with its own attribute (`data-theme`). Every combination gives the value the resolver document gives. Tailwind and JS outputs leave the combined tokens out: use the CSS custom properties. Nesting one modifier inside the other relies on CSS `@scope`; a browser without it keeps the outer value in the nested section.

## Keep the brand layer clean

```ts
lint: { rules: { 'semantic-must-alias': { severity: 'error', collections: ['Brand'] } } }
```

Fails when a brand token holds a raw value instead of an alias. `color-contrast` checks text and background pairs once per brand ([Lint rules](/reference/lint-rules/)).
