Run DTA on every push so broken tokens never reach `main`.

- `dta lint` exits with **2** on errors (broken aliases, rules set to `error`). Warnings exit with 0.
- `dta build` exits with **1** when the tokens can't be built, and then writes nothing.

All exit codes: [Exit codes](/reference/exit-codes/).

## Workflow

`npm create dta` adds DTA as a dev dependency, so CI installs your dependencies and runs it (Node.js 24 or newer). With pnpm or yarn, use `pnpm exec` or `yarn` instead of `npx`.

```yaml title=".github/workflows/tokens.yml"
name: tokens
on: [push, pull_request]
permissions:
  contents: read
jobs:
  tokens:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7
        with:
          node-version: 24
      - run: npm ci
      - name: Lint tokens
        run: npx design-token-authority lint
      - name: Build outputs
        run: npx design-token-authority build
```

Commit `tokens/`, not the build output.

## On pull requests

- **Token changes as a table:** `dta diff --tokens-only -f markdown -o token-changes.md`, for a comment or `>> $GITHUB_STEP_SUMMARY`. Needs the base commit: `fetch-depth: 0`, or `--base <ref|folder>`.
- **Screenshots explained by token:** [dta diff in pull requests](/guides/dta-diff-in-pull-requests/).
- **Pushing to Figma** (Enterprise): `dta push --dry-run --format markdown` on the pull request, `dta push --yes` on `main` only.

## Hard-coded values in code

`dta audit` finds colours, lengths and fonts in your code that equal a token, and names the token to use. It exits with **1** when it finds something.

```text
$ dta audit
src/Button.css
  3:15  #0057b8  background → Colors.Brand.Primary  var(--colors-brand-primary)
  5:12  16px     padding → Dimensions.spacing.4  var(--dimensions-spacing-4)
```

- It reads CSS, SCSS, JS/TS, the `<style>` blocks of Astro, Vue and Svelte, and Tailwind arbitrary values (`bg-[#2f55d4]`).
- A length is only matched to tokens of its kind: spacing, size, radius, stroke or font size, by the token's Figma scope or its name.
- Comments, `0`, percentages, `var()` fallbacks, tests and build output are skipped; mark a deliberate value with a `dta-audit-ignore` comment on its line or the line before.
- Folders and languages: the `audit` section of the [config](/reference/configuration/#audit).

Start advisory: record today's findings once, then only new ones are reported.

```sh
npx dta audit --update-baseline   # then commit .dta/audit-baseline.json
```

```yaml
- name: Audit hard-coded values
  run: npx design-token-authority audit --format markdown >> $GITHUB_STEP_SUMMARY
  continue-on-error: true # remove to make new findings fail the job
```

After a DTA upgrade the audit may find values it didn't check before (widths and heights, for example): fix them, or accept them with `--update-baseline`. `--format json` is for scripts ([schema](/schemas/dta.audit.schema.json)).
