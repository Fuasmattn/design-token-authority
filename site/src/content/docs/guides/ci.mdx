The two commands that belong in every pipeline:

- `dta lint` exits with **2** when it finds errors (dangling or circular aliases, default mode names, rules you set to `error`). Warnings print but exit with 0.
- `dta build` exits with **1** when the token files cannot be read or built, and writes the outputs otherwise.

All exit codes: [Exit codes](/reference/exit-codes/).

## Workflow

Until DTA is on npm, the workflow checks out the DTA repository into `.dta-cli` and runs its CLI (Node.js 24, pnpm). Not `.dta`: that folder is DTA's own, for the `dta diff` report and the audit baseline. After the release, the second checkout and the install step become `npx dta`.

```yaml title=".github/workflows/tokens.yml"
name: tokens
on: [push, pull_request]
permissions:
  contents: read
jobs:
  tokens:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/checkout@v4
        with:
          repository: Fuasmattn/design-token-authority
          path: .dta-cli
      - uses: pnpm/action-setup@v4
        with:
          package_json_file: .dta-cli/package.json
      - uses: actions/setup-node@v4
        with:
          node-version: 24
      - run: pnpm install --frozen-lockfile
        working-directory: .dta-cli
      - name: Lint tokens
        run: node .dta-cli/bin/dta.js lint
      - name: Build outputs
        run: node .dta-cli/bin/dta.js build
```

Commit the `tokens/` folder, not the build output: CI rebuilds it, and `dta clean` removes it locally.

## On pull requests

- **What changed in the tokens:** `dta diff --tokens-only -f markdown -o token-changes.md` writes the change set as a Markdown table for a comment or the job summary (`>> $GITHUB_STEP_SUMMARY`).
- **What it looks like:** with a `diff` section in the config, `dta diff` renders your stories at the base and the head and explains the differences by token. [dta diff in pull requests](/guides/dta-diff-in-pull-requests/) has ready-made actions for the status check and the comment.
- **Pushing to Figma from CI** (Enterprise): `dta push --yes` skips the typed confirmation. Run `dta push --dry-run --format markdown` on the pull request and the real push only on the main branch.

The token diff needs the base commit: check out with `fetch-depth: 0`, or pass `--base <ref|folder>`.

## Hard-coded values in code

`dta audit` scans your source for colours, lengths and font families that equal a token and names the token to use (CSS, SCSS, JS/TS/JSX/TSX, the `<style>` blocks of Astro, Vue and Svelte files, and Tailwind arbitrary values such as `bg-[#2f55d4]`). It exits with **1** when it finds something. On the `brand-ab` test fixture:

```text
$ dta audit
src/Button.css
  3:15  #0057b8  background → Colors.Brand.Primary  var(--colors-brand-primary)
  5:12  16px     padding → Dimensions.spacing.4  var(--dimensions-spacing-4)

src/Card.tsx
  3:30  #f3f4f6  bg-[…] → Colors.Surface.Muted  var(--colors-surface-muted)
  3:42  16px     p-[…] → Dimensions.spacing.4  var(--dimensions-spacing-4)
  3:71  Inter    fontFamily → Typography.Body.Family  var(--typography-body-family)

5 hard-coded values in 2 files could be tokens.
```

Lengths are compared with the tokens of their kind only: spacing (margin, padding, gap, inset), radius, stroke (border and outline widths) and font size, recognised by Figma scope or by name. Comments, `0`, percentages, `var()` fallbacks, `@font-face`, tests (`*.test.*`, `*.spec.*`), the token files and the build output are skipped; a deliberate value gets a `dta-audit-ignore` comment on its line or the line before. The scanned folders, ignore globs and languages are the `audit` section of the config ([Configuration](/reference/configuration/#audit)).

Add it as its own step, so its status is separate from lint and build. Start advisory, with today's findings recorded as accepted, and tighten it once the count is down:

```yaml
# Once, locally: dta audit --update-baseline, then commit .dta/audit-baseline.json
- name: Audit hard-coded values
  run: node .dta-cli/bin/dta.js audit --format markdown >> $GITHUB_STEP_SUMMARY
  continue-on-error: true # advisory; remove to make new findings fail the job
```

With the baseline, later runs report only new findings (a finding is recognised by file, value and property, so moving lines does not make it new). `--format json` prints the findings for scripts and agents ([schema](/schemas/dta.audit.schema.json)).
