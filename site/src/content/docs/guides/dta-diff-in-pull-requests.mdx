`dta diff` screenshots your stories at the base and the head of a pull request and explains each change by the token that caused it. On GitHub you get:

- **A status check**, "dta diff": green, pending with _changes to review_, or red with _unexplained changes_.
- **One comment**, updated on every push, linking the full report.

Everything runs in your CI; nothing is stored between runs.

## Before you start

```sh
npx dta init --diff
```

Detects your Storybook (or asks which pages), package manager and branch, and writes the `diff` config, the GitHub workflow and `playwright-core`. Add `--yes` to take the defaults.

```sh
npx dta diff --check
```

Checks the setup without rendering anything.

```sh
npx dta diff
```

Renders a report locally, in `.dta/diff/index.html`.

## Which pages it renders

`diff.stories` in the config:

- **Pages of your site:** a list of paths, rendered from `diff.outDir`. `/pricing` is served from `pricing`, `pricing.html` or `pricing/index.html`.

  ```ts title="dta.config.ts"
  diff: {
    build: 'npm run build',
    outDir: 'dist',
    stories: ['/', '/pricing'],
  }
  ```

- **Storybook:** `stories: { type: 'storybook' }` renders every story ([dta diff with Storybook](/guides/dta-diff-with-storybook/)).
- **Your own story pages:** `stories: { manifest: 'stories/manifest.json' }`, a `dta.stories/1` file listing `id`, `title`, `url` and optional `viewports` per page.

`npx dta diff --list` shows what it found.

## Approving changes

Changes are reviewed once per token change, not per screenshot. When you have looked, add the **`dta-diff-approved`** label: the status turns green and the comment says **approved**. A new push needs a new review; removing the label withdraws it.

What needs a look at all is set by thresholds, as ratios of changed pixels (default `0`: every change counts):

```ts
diff: { thresholds: { explained: 0, unexplained: 0 } }
```

## Reading the report

- **Changed stories** show the screenshot with every element a changed token touches outlined and labelled: `Colors.Brand.Primary · 500 → 600`.
- **Show before** flicks to the base screenshot.
- **Unexplained changes** (no token accounts for them) show the changed pixels in orange.
- **Before and after** are named by branch and commit, for example `main · 2ee9b31` and `feature/x · 9f3c1a2`.

## Change your setup later

Run `npx dta init` again. It lists what it would change and asks once. Keys and workflow files you edited are kept.

## Publishing the report

Without a publish hook, the report is a workflow artifact and the comment has no images. With one, the comment shows thumbnails and links the hosted report.

A hook is any command: it gets the report folder (last argument and `DTA_REPORT_DIR`) and prints the public URL on its **last line**.

```ts
diff: {
  publish: 'sh .github/dta-diff-publish.sh'
}
```

If the URL is elsewhere in the output: `publish: { command: 'sh publish.sh', url: '$.deploy_url' }` (a JSON path, or a regex whose first group is the URL). Try a hook on your last report without rendering again:

```sh
npx dta diff --from-report --publish "sh .github/dta-diff-publish.sh"
```

:::caution[Forks]
A report from a fork is built from untrusted code. The example workflows publish only for branches of your own repository.
:::

## Troubleshooting

Start with `npx dta diff --check`:

| Check       | Fails when                               | Fix                                                                                         |
| ----------- | ---------------------------------------- | ------------------------------------------------------------------------------------------- |
| config      | no `diff` section                        | `dta init`, or add `diff: { outDir: 'dist' }`                                               |
| browser     | `playwright-core` or Chromium is missing | `npm i -D playwright-core` and `npx playwright install chromium`, or set `DTA_BROWSER_PATH` |
| git history | shallow checkout                         | `fetch-depth: 0` on `actions/checkout`, or `--base <ref\|dir>`                              |
| base        | no default branch or merge base          | `--base <ref>` or `diff.base`                                                               |
| stories     | no pages or stories in the output        | build first (`diff.build`), then check `diff.outDir` and `diff.stories`                     |

In CI a missing browser stops the run; locally `dta diff` warns and shows token changes only. A base that doesn't build stops the run with its output.

## Without GitHub

`dta diff --publish "<command>"` works in any CI, and `--format json` or `summary.md` feed whatever posts your comments.
