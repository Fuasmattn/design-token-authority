---
title: dta diff with Storybook
description: Screenshot every story of a static Storybook build and explain the changes by token, without writing a stories manifest.
---

`dta diff` needs to know which pages to screenshot. A static site lists them in a stories manifest; a Storybook build already has the list: `index.json`. Point `dta diff` at the build and it renders each story on its own, through Storybook's `iframe.html` (the story without the Storybook interface).

## Configure

```ts title="dta.config.ts"
export default {
  // …tokens, outputs
  diff: {
    // A fresh checkout of the base needs its dependencies first.
    setup: 'npm ci --prefer-offline',
    // Build your tokens, then Storybook, at the base and at the head.
    build: 'npx dta build && npm run build-storybook',
    outDir: 'storybook-static',
    stories: { type: 'storybook' },
    viewports: [1280, 390],
  },
}
```

Check what it would render, after one build:

```sh
npx dta diff --list
```

`dta diff` reads `index.json` of Storybook 7 and later (v4 and v5); `stories.json` of Storybook 6 is not supported.

## Which stories

- Only stories are rendered. Docs pages (MDX, autodocs) are left out.
- A story tagged **`skip-dta-diff`** is left out. Use another tag with `excludeTags`.
- `exclude` takes regular expressions matched against story ids.

```ts
stories: {
  type: 'storybook',
  index: 'index.json',              // inside outDir (the default)
  excludeTags: ['skip-dta-diff', 'experimental'],
  exclude: ['^internal-'],          // story ids
},
```

```js title="Button.stories.js"
export const Playground = { tags: ['skip-dta-diff'] } // interactive only, not for screenshots
```

Each story is captured once Storybook has rendered it (the iframe's body gets `sb-show-main`), after network idle, with animations off. The viewports apply to every story.

## How changes are explained

The explanation works by reverting each changed token in the rendered page, so it needs your stories to use the tokens as CSS custom properties: import the CSS `dta build` writes in `.storybook/preview.js`.

```js title=".storybook/preview.js"
import '../output/css/variables.css'
import '../output/css/themes/branda.css' // one theme per brand, selected with [data-brand]
```

Values your build bakes in as literals (a Tailwind config with resolved colors, JavaScript reading token values) cannot be reverted: the pixels they change stay **unexplained**. Everything else (the report, the pull-request comment, the status check) works as described in [dta diff in pull requests](/guides/dta-diff-in-pull-requests/).

## Tried on a small Storybook

A Storybook 10 project with two Button stories and a Card, at two commits: `space` 8 → 12 px and the Card's corner radius 12 → 28 px (a literal in the story).

```text
changed   components-button--primary@600  0.13% explained by space
changed   components-button--outline@600  0.10% explained by space
changed   components-card--default@600    0.09% unexplained: 436 px
```

The same commit against itself renders all three stories identically.
