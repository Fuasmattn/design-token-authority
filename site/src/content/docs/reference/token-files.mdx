The files DTA reads and writes: one JSON file per collection and mode, in the [DTCG](https://tr.designtokens.org/format/) format.

## The format

- **File name:** `{Collection}.{Mode}.json`, for example `Brand.BrandA.json`. The name splits at the first dot, so a collection name has no dot.
- **One-mode files:** `{Collection}.tokens` or `.tokens.json` hold a collection with the mode `Value`. Don't also keep a per-mode file for the same collection and mode.
- **Groups** nest freely; a token's path (`Colors.Brand.Primary`) is its name, unique across all collections.
- **A token** has a `$value` and a type: its own `$type`, else the type its alias points to, else the closest group's `$type`. Optional: `$description`, `$deprecated`, `$extensions`.
- **Aliases:** `{Colors.Foundation.Blue.500}`, or a `$ref` JSON Pointer (`#/Colors/Blue/$value/components/0`), for a whole value or one part of a composite.
- **`$root`** is a group's own token (`{color.accent.$root}`); **`$extends`** gives a group another group's tokens in the same file.
- **Names** must not contain `{` or `}`; a `.` is a warning (DTCG 2025.10 doesn't allow it).
- **`$extensions["com.figma"]`** (`hiddenFromPublishing`, `scopes`, `codeSyntax`) is kept when you push.

```json
{
  "Colors": {
    "Brand": {
      "Primary": {
        "$type": "color",
        "$value": "{Colors.Foundation.Blue.500}",
        "$description": "Primary brand color"
      }
    }
  }
}
```

### Types and values

DTA reads every [DTCG 2025.10](https://www.designtokens.org/tr/2025.10/format/) type and checks each value (`invalid-value`). An unknown type is an error. How each is built: [Outputs](/reference/outputs/#dtcg-202510-types); `dta push` skips what Figma can't hold (`not-pushable`).

| Type                                                                      | `$value`                                                             |
| ------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `color`                                                                   | `{ "colorSpace": "oklch", "components": [0.7, 0.15, 250] }` or a hex |
| `dimension`, `duration`                                                   | `{ "value": 16, "unit": "px" }` (`px`, `rem`; `ms`, `s`) or `"16px"` |
| `fontFamily`, `fontWeight`                                                | `"Inter"` or `["Inter", "sans-serif"]`; `700` or `"bold"`            |
| `cubicBezier`, `number`                                                   | `[0.5, 0, 1, 1]`; `1.5`                                              |
| `shadow`, `border`, `transition`, `typography`, `gradient`, `strokeStyle` | objects as in the DTCG format; each part may be an alias             |
| `string`, `boolean`                                                       | any scalar, as Figma variables hold them (not in DTCG)               |

### Resolver documents

A DTCG [resolver document](https://www.designtokens.org/tr/2025.10/resolver/) (`*.resolver.json`) in the tokens folder describes the set instead of the file names: **sets** of files, **modifiers** with **contexts** (light and dark, brand A and B) and the order they apply in. `tokens.resolver` picks one when there are several.

```json title="tokens/app.resolver.json"
{
  "version": "2025.10",
  "sets": { "core": { "sources": [{ "$ref": "sets/color.json" }] } },
  "modifiers": {
    "theme": {
      "contexts": {
        "light": [{ "$ref": "themes/light.json" }],
        "dark": [{ "$ref": "themes/dark.json" }]
      },
      "default": "light"
    }
  },
  "resolutionOrder": [{ "$ref": "#/sets/core" }, { "$ref": "#/modifiers/theme" }]
}
```

- A **set** becomes a collection with one mode; a **modifier** a collection with one mode per context.
- Sources merge in order, the last one wins; aliases resolve after merging.
- `dta build` writes one theme per context: `themes/theme-dark.css` on `[data-theme="dark"]`. List a modifier's contexts in `brands` to switch them with `data-brand` instead.
- `modifiers: { theme: 'dark' }` in the config changes the default context.
- Token files the document doesn't name are reported (`not-in-resolver`) and not read.
- Several modifiers combine freely: [Brands and themes](/guides/brands-and-themes/#brands-and-themes-together).

### JSON Schema

[`/schemas/token-file.schema.json`](/schemas/token-file.schema.json) describes one file, for your editor or your own exporter. It checks the shape; `dta lint` checks the rest (alias targets, type mismatches, duplicate names).

## Getting your tokens into this format

| Way                                    | Needs           |
| -------------------------------------- | --------------- |
| `dta pull` (Figma REST API)            | Enterprise plan |
| A Figma plugin export, converted below | Any plan        |
| Your own files or tooling              | Nothing         |

### Converting third-party exports

`dta pull --from-file` converts known single-file exports:

| Format      | Recognised by                             |
| ----------- | ----------------------------------------- |
| `tokenhaus` | `$extensions.com.figma.modes` at the root |

Files already in the format above need no conversion. Anything else is reported as unknown: convert it yourself, or [contribute an adapter](/contribute/). The [playground](/playground/) checks a file in your browser the same way.
