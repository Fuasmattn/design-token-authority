What `dta lint` checks in the token files of `tokens.dir`. Errors exit with 2, warnings with 0. `dta push` runs the same check first (`--skip-lint` skips it).

## Always on

| Rule                    | Severity | Finds                                                   |
| ----------------------- | -------- | ------------------------------------------------------- |
| `no-dangling-aliases`   | error    | An alias whose target does not exist                    |
| `no-circular-aliases`   | error    | Aliases that point at each other in a circle            |
| `no-default-mode-names` | error    | Modes still called `Mode 1`, `Mode 2` (Figma's default) |

```txt
|    error Alias {Colors.Foundation.Sky.550} references non-existent token "Colors.Foundation.Sky.550" [no-dangling-aliases]
```

The playground's "Example with problems" shows one finding of each.

### Broken aliases fail the build

A dangling or circular alias has no value, so `dta build` fails on it too: same message, exit code 1, and **no file is written**. Files from an earlier build stay as they were. A default mode name does not stop the build.

## Configurable

Set under `lint.rules`. A configured rule is a warning unless you set `severity: 'error'`; `'off'` disables it.

```ts title="dta.config.ts"
lint: {
  rules: {
    'semantic-must-alias': { severity: 'error', collections: ['Brand'] },
    'color-contrast': { pairs: [['Colors.Text.Default', 'Colors.Surface.Default']] },
  },
},
```

| Rule                  | Fails or reports                                                  | Options                                                                             |
| --------------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `semantic-must-alias` | a token in the listed collections holds a raw value, not an alias | `collections`                                                                       |
| `naming-pattern`      | a path segment doesn't match its collection's regular expression  | `patterns`: collection → regex                                                      |
| `naming-case`         | a path segment isn't in its collection's case style               | `collections`: collection → `kebab-case`, `camelCase`, `PascalCase` or `snake_case` |
| `naming-depth`        | a token path has fewer or more segments than allowed              | `collections`: collection → `{ min, max }`                                          |
| `no-spaces`           | spaces in collection names or path segments                       | —                                                                                   |
| `collection-pattern`  | a collection name doesn't match the regular expression            | `pattern` (not anchored: write `^…$` for the whole name)                            |
| `color-contrast`      | a text and background pair is below the WCAG ratio                | `pairs`: `[foreground, background]`; `minRatio` (default 4.5)                       |
| `no-duplicate-values` | a raw value appears more than once (one could be an alias)        | —                                                                                   |

- **Naming rules:** scale steps (`700`, `0-5`, `2xl`) fit every case style; `$root` is not checked or counted. An invalid regular expression is a config error.
- **`color-contrast`** checks each pair in every brand or mode it can differ in, through aliases, and names the mode in the finding. Colours outside sRGB are checked clipped (`contrast-clipped` warning). A pair that can't be resolved is skipped with a warning.

```txt
|    warn Contrast ratio 4.39:1 between "Colors.Text.Muted" (#6b7280) and "Colors.Surface.Muted" (#f3f4f6) is below 4.5:1 in BrandA [color-contrast]
```

## `--fix`

Accepted, but there are no fixes yet: it says so and lints as usual.
