What `dta build` writes. Everything goes to `output/` unless `outputs.css.outDir`, `outputs.tailwind.outDir`, `outputs.ios.outDir` or `outputs.android.outDir` say otherwise. The [playground](/playground/) builds the web files in your browser.

| File                                         | Content                                                                        |
| -------------------------------------------- | ------------------------------------------------------------------------------ |
| `output/css/variables.css`                   | Single-mode collections on `:root`; aliases stay `var()` references            |
| `output/css/base.css`                        | The same, with resolved values                                                 |
| `output/css/themes/<brand>.css`              | One brand's tokens on `[data-brand="<brand>"]` (lower case)                    |
| `output/js/colorpalette.js`                  | Resolved values as exports: `export const ColorsFoundationBlue500 = "#0057b8"` |
| `output/tailwind/tailwind.css`               | Tailwind v4 `@theme` for the single-mode collections                           |
| `output/tailwind/<brand>/tailwind.css`       | Tailwind v4 `@theme` for one brand, resolved                                   |
| `output/tailwind/tailwind.tokens.ts`         | Tailwind v3 `theme.extend` object                                              |
| `output/tailwind/<brand>/tailwind.tokens.ts` | The same for one brand, resolved                                               |

## Choosing outputs

`outputs.formats` lists what to write; without it, the four web outputs. Native outputs are written only when listed.

```ts title="dta.config.ts"
outputs: {
  formats: ['css', 'tailwind-v4'], // also: 'tailwind-v3', 'js', 'ios-swift', 'android-xml', 'android-compose'
}
```

| Format            | Files                                                             |
| ----------------- | ----------------------------------------------------------------- |
| `css`             | `variables.css`, `base.css`, `themes/<brand>.css`                 |
| `tailwind-v4`     | `tailwind.css`, `<brand>/tailwind.css`                            |
| `tailwind-v3`     | `tailwind.tokens.ts`, `<brand>/tailwind.tokens.ts`                |
| `js`              | `js/colorpalette.js`                                              |
| `ios-swift`       | `ios/DesignTokens.swift`, `ios/BrandTokens+<Brand>.swift`         |
| `android-xml`     | `android/main/values/colors.xml`, `dimens.xml`, `<brand>/values/` |
| `android-compose` | `android/compose/DesignTokens.kt`                                 |

## Breakpoint modes

Name the collection whose modes are screen sizes in `breakpoints`, and `variables.css` gets its default mode on `:root` and every other mode in its media query, in the order of `modes`:

```ts title="dta.config.ts"
breakpoints: {
  collection: 'ScreenType',
  default: 'Mobile',
  modes: { Tablet: '(min-width: 768px)', Desktop: '(min-width: 1024px)' },
}
```

```css title="output/css/variables.css (excerpt)"
:root {
  --spacing-padding: var(--dimensions-spacing-2);
}
@media (min-width: 768px) {
  :root {
    --spacing-padding: var(--dimensions-spacing-4);
  }
}
```

- **The queries are yours**, written as given and not sorted: `min-width` from small to large, or `max-width` from large to small. A later matching block wins.
- **Media queries only:** a selector is rejected, and every mode except the default needs a query (one without is left out, with a warning).
- **Tailwind v4:** an `@theme inline` block reads the switching properties, so `p-spacing-padding` follows the media queries.
- **Resolved files have no breakpoints:** `base.css`, the JS palette and Tailwind v3 use the default mode.
- **Brands:** a breakpoint token that aliases a brand token is repeated in every theme, inside the same media queries.

Without `breakpoints`, such a collection only resolves aliases (through its first mode, alphabetically).

## Single-mode tokens that alias brand tokens

A single-mode token whose alias reaches a brand token (`button.background` → `{action.background}`) is written on `:root` and again in every `themes/<brand>.css`, so a nested `data-brand` element gets its own brand. `base.css` has no brands: it resolves such a token through the first brand, alphabetically.

## When the build fails

A dangling or circular alias has no value, so `dta build` reports it (as `dta lint` does), writes **no file** and exits with 1. An earlier build is left as it was. Example output: [Lint rules](/reference/lint-rules/#broken-aliases-fail-the-build).

## Names and values

- **Names** are the token path in kebab case: `Colors.Foundation.Blue.500` → `--colors-foundation-blue-500`. Repeated neighbouring words collapse (`Colors/Colors Brand/Primary` → `--colors-brand-primary`).
- **Numbers** get `px` when their Figma scope says length (gap, width and height, radius, stroke, effects), become decimals for opacity (`50` → `0.5`), and stay plain otherwise.
- **Descriptions** become comments.

### DTCG 2025.10 types

| Type                                           | CSS                                                                          |
| ---------------------------------------------- | ---------------------------------------------------------------------------- |
| `color`                                        | hex or `rgba()` for sRGB; other spaces as written: `oklch(0.7 0.15 250)`     |
| `dimension`, `duration`                        | with their unit: `16px`, `1rem`, `0.15s`                                     |
| `fontFamily`, `fontWeight`                     | a font stack; weights as numbers (`semi-bold` → `600`)                       |
| `cubicBezier`                                  | `cubic-bezier(0.5, 0, 1, 1)`                                                 |
| `shadow`, `border`, `transition`, `typography` | the CSS shorthand; parts that are references stay `var()` in `variables.css` |
| `gradient`                                     | the colour stops: use as `linear-gradient(to right, var(--gradient-brand))`  |
| `strokeStyle`                                  | the keyword (`dashed`); a dash pattern becomes `dashed`                      |

A `$root` token is named after its group plus `root` (`--color-accent-root`); a `$ref` is written resolved. Tailwind gets theme keys for `fontFamily`, `fontWeight`, `shadow`, `cubicBezier`, and for a `dimension` by the words in its name (`radius`, `spacing`, `gap`, `font-size`, `blur`, `breakpoint`).

## Native outputs

Swift (SwiftUI), Android resource XML and Kotlin (Jetpack Compose), from resolved values with the alias chain as a comment. `outputs.android.package` sets the Kotlin package (default `designtokens`).

- **Brands are themes.** Tokens whose alias chain goes through the brand collection are written once per brand; everything else is shared. Swift and Compose get a `BrandTheme` protocol or interface and one implementation per brand (`let theme: BrandTheme = BrandA()`); Android XML gets `main/values/` plus `<brand>/values/` for product-flavour source sets.
- **Breakpoints:** native apps have no media queries, so they use `breakpoints.default` (a warning names the modes left out). Other multi-mode collections no brand selects are read in their default mode.
- **Names:** the first path segment is the group: `DesignTokens.Colors.foundationBlue500` (Swift), `DesignTokens.Colors.FoundationBlue500` (Compose), `colors_foundation_blue_500` (XML). Clashing names are a warning; the second is left out.
- **Never silently:** composite types, values without a native form (`50%`, `1em`), tokens that don't resolve in every brand and clipped colours are counted in warnings.

| Token                                   | Swift              | Android XML | Compose        |
| --------------------------------------- | ------------------ | ----------- | -------------- |
| `color` (converted to sRGB)             | `Color(.sRGB, …)`  | `#AARRGGBB` | `Color(0x…)`   |
| length (`dimension`, or a length scope) | `CGFloat`          | `16dp`      | `16.dp`        |
| font size                               | `CGFloat`          | `16sp`      | `16.sp`        |
| other `number`, `fontWeight`            | `Double`           | not written | `Int`/`Double` |
| `string`, `fontFamily`                  | `String`           | not written | `String`       |
| `boolean`                               | `Bool`             | not written | `Boolean`      |
| `duration`                              | `TimeInterval` (s) | not written | `Long` (ms)    |

## Not built

- Breakpoints by selector or container query.
- Native: composite types, light and dark as native themes, size classes, `values-night`, asset catalogs.
- The web outputs only in the playground; native files come from `dta build`.
