DTA's token files use the W3C [Design Tokens Community Group](https://www.designtokens.org/) (DTCG) format, version [2025.10](https://www.designtokens.org/TR/2025.10/). This page gives the idea and where DTA differs; the spec has the details.

| Module                                                        | What it defines                                                                                                                                                         |
| ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Format](https://www.designtokens.org/tr/2025.10/format/)     | Tokens (objects with `$value`) and groups, `$type`, `$description`, `$extensions`, `$deprecated`, aliases (`{group.token}`, `$ref`), `$root`, `$extends`, and the types |
| [Color](https://www.designtokens.org/tr/2025.10/color/)       | Colour values as objects in any CSS Color 4 space                                                                                                                       |
| [Resolver](https://www.designtokens.org/tr/2025.10/resolver/) | Themes, brands and other contexts: sets, modifiers and the order in which they apply                                                                                    |

## Where DTA differs

- **One file per collection and mode**, in the shape of Figma variables: `Brand.BrandA.json`, `Brand.BrandB.json`.
- **Every 2025.10 type and reference** is read and checked against its type.
- **Not yet:** `$extends` from one per-mode file into another (it works within a file and in resolver documents).

The full format: [Token files](/reference/token-files/).
