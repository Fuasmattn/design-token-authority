The **Design Tokens Community Group (DTCG)** is a W3C community group that writes a vendor-neutral file format for design tokens. Its first stable version, **2025.10**, was published on 28 October 2025 as three modules: [Format](https://www.designtokens.org/tr/2025.10/format/), [Color](https://www.designtokens.org/tr/2025.10/color/) and [Resolver](https://www.designtokens.org/tr/2025.10/resolver/). DTA's token files follow the Format module, restricted to what a Figma variable can hold. This page and the next three walk through the format and mark where DTA differs.

## Tokens and groups

A token file is a JSON object. Any object with a `$value` is a **token**; any object without one is a **group**. Groups nest freely, and the path of keys to a token is its name. An object with both a `$value` and child tokens is invalid.

Properties that start with `$` belong to the format; everything else is a name. Names are case-sensitive, must not start with `$`, and must not contain `{`, `}` or `.` (those are used by aliases).

| Property       | On              | Meaning                                                                                           |
| -------------- | --------------- | ------------------------------------------------------------------------------------------------- |
| `$value`       | token           | The value, or an alias to another token. Required.                                                |
| `$type`        | token or group  | What kind of value it is ([Types](/learn/dtcg/types/)). A group's `$type` applies to its tokens.  |
| `$description` | token or group  | Plain text for people and tools.                                                                  |
| `$extensions`  | token or group  | Vendor data under reverse-domain keys, such as `com.figma`. Tools must keep what they don't know. |
| `$deprecated`  | token or group  | `true`, or a string that says what to use instead.                                                |
| `$root`        | group (a child) | A token that stands for the group itself ([Aliases](/learn/dtcg/aliases/)).                       |
| `$extends`     | group           | Inherit the tokens of another group ([Aliases](/learn/dtcg/aliases/)).                            |

The spec suggests the file extension `.tokens` or `.tokens.json` and the media type `application/design-tokens+json`.

## What DTA does differently

DTA's files are the DTCG format in the shape of Figma variables. The [Token files](/reference/token-files/) reference has the details; the differences that matter when you come from the spec:

- **One file per collection and mode.** `Brand.BrandA.json` and `Brand.BrandB.json` hold the same token names with different values. The spec expresses this with the [resolver module](/learn/dtcg/resolver/), which DTA does not read yet.
- **`$type` on every token.** DTA does not inherit `$type` from groups yet. A token without its own `$type` is an error (`missing-type`).
- **Four types.** `color`, `number`, `string` and `boolean`, the types of Figma variables. See [Types](/learn/dtcg/types/).
- **`$description` and `$extensions`** are read and written back. `$deprecated` and anything else DTA does not use stay in the file as written.
- **`.json` file names.** DTA reads `{Collection}.{Mode}.json`, not `.tokens`.

Closing these gaps (group types, the 2025.10 colour and dimension values, `$root`, `$extends`, `$ref`, resolver documents) is tracked in TICKET-094.
