A token's type says what its value means, so that tools can check it and turn it into the right code for each platform. The spec resolves a token's type in this order: its own `$type`; for an alias, the type of the token it points to; the `$type` of the nearest group above it. If none applies, the token is invalid. Tools must not guess the type from the value.

## The DTCG types

| Kind      | Types                                                                     | Value                                                                |
| --------- | ------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| Primitive | `color`                                                                   | an object: `colorSpace`, `components`, optional `alpha` and `hex`    |
|           | `dimension`                                                               | an object: `value` and `unit` (`px` or `rem`)                        |
|           | `duration`                                                                | an object: `value` and `unit` (`ms` or `s`)                          |
|           | `fontFamily`                                                              | a string, or a list of strings                                       |
|           | `fontWeight`                                                              | a number from 1 to 1000, or a name such as `bold`                    |
|           | `cubicBezier`                                                             | four numbers                                                         |
|           | `number`                                                                  | a JSON number                                                        |
| Composite | `strokeStyle`, `border`, `transition`, `shadow`, `gradient`, `typography` | an object (or a list) whose parts are values or aliases of the above |

Colours in 2025.10 are objects so that they can live in any CSS Color 4 space (`srgb`, `display-p3`, `oklch` and more); `hex` is an optional 6-digit fallback. From the [Color module](https://www.designtokens.org/tr/2025.10/color/):

```json title="DTCG 2025.10 (not read by DTA yet)"
{
  "Brand blue": {
    "$type": "color",
    "$value": { "colorSpace": "srgb", "components": [0, 0.4, 1], "hex": "#0066ff" }
  }
}
```

The full definitions of every type are in the [Format module](https://www.designtokens.org/tr/2025.10/format/).

## The types DTA reads

DTA reads the four types of Figma variables. Two of them, `string` and `boolean`, are not DTCG types; Figma has them, so DTA keeps them.

| DTA type  | Value in the file   | DTCG counterpart                     | Becomes in CSS                                                                        |
| --------- | ------------------- | ------------------------------------ | ------------------------------------------------------------------------------------- |
| `color`   | a CSS colour string | `color` (as an object)               | the colour as written                                                                 |
| `number`  | a number            | `number`, `dimension`, `fontWeight`… | `px` when the Figma scope is a length (gap, size, radius, stroke, effect), else as is |
| `string`  | a string            | `fontFamily` and others              | the string                                                                            |
| `boolean` | `true` or `false`   | none                                 | `true` or `false`                                                                     |

A length is a `number` plus a Figma scope, because that is how Figma stores it:

```json
"radius": {
  "4": {
    "$type": "number",
    "$value": 4,
    "$extensions": { "com.figma": { "scopes": ["CORNER_RADIUS"] } }
  }
}
```

The [Outputs](/reference/outputs/) reference lists every rule.

## What happens to other types

A token with a type DTA does not know is reported and left alone: it stays in the file, untouched, but is not part of the build. A DTCG `dimension` next to the Figma-style number:

```json title="tokens/Primitives.Value.json"
{
  "space": {
    "small": { "$type": "dimension", "$value": { "value": 8, "unit": "px" } },
    "small-figma": { "$type": "number", "$value": 8 }
  }
}
```

```text
$ dta lint
T   ✔  dta lint
|
o  Linting complete.
|
!  warning [unsupported-type] Token "space.small" has unsupported $type "dimension"; it is left out of the model and kept as is. (Primitives.Value.json)
|
*  No lint violations found.
|
—  All clean!
```

Two spec features fail outright today: a token that only gets its type from a group (`missing-type`), and a 2025.10 colour object (`invalid-value`, the value is not a string, number or boolean). Reading the DTCG value shapes is part of TICKET-094.
