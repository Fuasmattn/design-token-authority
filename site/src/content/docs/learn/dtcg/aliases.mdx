An **alias** (the spec also says reference) is a token whose value is another token. Aliases are what turn a list of values into a system: `button.background` says "the action colour", not "`#1f5fd1`", and changes when the action colour changes.

## Curly braces

The common form is the token's path in braces, with dots between the parts:

```json
"link": { "$type": "color", "$value": "{color.blue.500}" }
```

In the spec, a curly-brace alias:

- points at a **whole token**, never a group, and stands for its `$value`;
- may point at another alias; tools follow the chain to the end;
- must not form a cycle: an alias that leads back to itself is an error;
- gives the token its type if it has none of its own.

Inside a composite value, each part can be an alias of its own, for example the `color` of a `shadow`.

## `$ref`, `$root` and `$extends`

2025.10 adds three more ways to connect things. DTA does not read them yet (TICKET-094); this is the spec's syntax.

**`$ref`** is a JSON Pointer. Unlike braces it can point into a value, for example one channel of a colour:

```json title="DTCG 2025.10 (not read by DTA yet)"
{ "$ref": "#/color/blue/$value/components/0" }
```

**`$root`** is a token that stands for its group, so a group can have a value and children. It is referenced with its full path, `{color.accent.$root}`:

```json title="DTCG 2025.10 (not read by DTA yet)"
{
  "color": {
    "accent": {
      "$root": { "$type": "color", "$value": "{color.blue.600}" },
      "light": { "$type": "color", "$value": "{color.blue.400}" }
    }
  }
}
```

**`$extends`** makes a group inherit the tokens of another group; a token at the same path replaces the inherited one. That is a component override in one line:

```json title="DTCG 2025.10 (not read by DTA yet)"
{
  "button-danger": {
    "$extends": "{button}",
    "background": { "$type": "color", "$value": "{color.red.600}" }
  }
}
```

## How DTA resolves aliases

DTA reads braces, with one rule the spec does not need: **token names are unique across all collections**. An alias carries no file or collection name, so `{color.blue.500}` in `Brand.BrandB.json` finds the token in `Primitives.Value.json`. Figma variables work the same way (in Figma the path reads `color/blue/500`; DTA converts between the two when it pulls and pushes).

- `dta lint` fails on aliases that point nowhere and on cycles.
- `dta graph` counts aliases, chain depth, dangling aliases and orphans, and `dta graph --format html` draws them.
- `dta build` keeps aliases as `var()` references in `variables.css` and in the theme files, so a changed primitive reaches everything that uses it, and resolves them to values in `base.css`.

The [tiers pattern](/learn/patterns/tiers/) shows a two-step chain (component → semantic → primitive) with the `dta graph` output.
