Headings, gutters and section spacing often differ between a phone and a desktop. In Figma this is usually a collection with one mode per breakpoint, so designers can switch a frame from Desktop to Mobile and see the layout change. On disk that is one file per breakpoint.

:::caution[Not in the build yet]
`dta build` does not write breakpoint CSS yet: the output has the primitives, but no `--heading-size` or `--layout-gutter`. Breakpoint modes in the build (media queries per mode) are TICKET-091. Until then, write the media queries yourself against the primitives, or keep breakpoint values out of the token build.
:::

## Trade-offs

- **Modes or fluid values.** Breakpoint modes give fixed steps that match the Figma frames exactly. A fluid value (a CSS `clamp()` between a minimum and a maximum) needs no modes and no media queries, but has no single number for Figma to show, so it is usually a code-side decision built from two tokens.
- **Which breakpoints.** The modes are named sizes; the pixel widths at which they apply are not tokens in Figma's model. Keep them in one place in code (or as `number` tokens of their own) so that design and CSS agree.
- **Keep it small.** Only what really changes with the screen belongs here: type sizes, spacing, layout widths. Colours and radii that do not change stay in the brand or semantic tier.
