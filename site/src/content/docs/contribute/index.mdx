Everything lives in [one repository](https://github.com/Fuasmattn/design-token-authority). You need Node.js 24 or newer and pnpm.

```sh
pnpm install
pnpm dta --help      # the CLI from the sources
pnpm site:dev        # this website
```

## Packages

A pnpm workspace of small packages behind one CLI:

| Package            | Does                                                        |
| ------------------ | ----------------------------------------------------------- |
| `@dta/core`        | Token model, token files, aliases, graph, colour            |
| `@dta/figma`       | Figma REST client, pull and push, plugin-export adapters    |
| `@dta/build`       | CSS, JavaScript, Tailwind and native outputs                |
| `@dta/lint`        | Lint rules                                                  |
| `@dta/visual-diff` | `dta diff`: token changes, screenshots, attribution, report |
| `@dta/cli`         | Commands, config, terminal UI; the only user-facing package |
| `@dta/testkit`     | Private test helpers: Figma fake, snapshots                 |
| `create-dta`       | `npm create dta`                                            |

`site/` is this website, `actions/` the GitHub actions for `dta diff`.

## Rules every change follows

- **Package boundaries:** import other packages by name (`@dta/core`), never by path; `@dta/core` depends on no other package.
- **Variable names are unique** across collections.
- **Push never deletes** in Figma; deleting is `dta prune`.
- **The website uses only its tokens and design-system components**; anything new becomes a component first, with a docs page and a story.
- **No real customer names**: BrandA, BrandB.
- **Imports use `.js` extensions** in TypeScript sources.

## Tests

- Each package is tested through its public API (`*.test.ts` next to the sources).
- `test/snapshots/` holds the CLI's output on the fixtures. A failing snapshot means the output changed: fix the code, or re-record that one scenario on purpose (`pnpm snapshot:record --scenario <fixture>/<scenario>`).
- Figma is faked from recordings; CI needs no secrets.

Every change passes the gates CI runs:

```sh
pnpm run prettier:check
pnpm run typecheck
pnpm run guardrails:boundaries
pnpm test
pnpm run snapshot:check
```

## Specs, tickets and decisions

- **Specs** (`docs/specs/`) describe an epic: the problem and the decisions.
- **Tickets** (`docs/tickets/`, index in `000-index.md`) are one deliverable each, with acceptance criteria.
- **ADRs** (`docs/adr/`) record decisions that shape the code.

A good first contribution: a plugin-export adapter in `packages/figma/src/adapters/`, with a fixture.

## Releases

Run the **Release** workflow from `main` (Actions → Release, with `patch`, `minor`, `major` or a version). It sets the versions, writes the changelog from the commit messages, tags, and publishes both packages to npm with trusted publishing (no npm token). A release stops when `pnpm audit --prod` finds a known vulnerability. Report vulnerabilities as described in [SECURITY.md](https://github.com/Fuasmattn/design-token-authority/blob/main/SECURITY.md).

## The website

Vercel deploys `main` to [dta.martinprinz.dev](https://dta.martinprinz.dev) and a preview for every pull request, with the settings in `vercel.json`. The site's address for the sitemap, `llms.txt` and the schemas is `SITE_URL` in `site/site-url.mjs`.
