## Collections, modes and token files

DTA follows Figma's variable model. A **collection** groups variables; a **mode** is one set of values for all of them (a brand, a theme, a breakpoint). On disk, every collection and mode is one JSON file named `{Collection}.{Mode}.json`:

```text
tokens/Primitives.Value.json        one collection, one mode
tokens/Brand(Alias).BrandA.json     one collection, a mode per brand
tokens/Brand(Alias).BrandB.json
tokens/ScreenType.Desktop.json      one collection, a mode per breakpoint
```

Inside, the files use the [W3C Design Tokens (DTCG)](https://tr.designtokens.org/format/) format: nested groups, and tokens with `$type` and `$value`. The full format: [Token files](/reference/token-files/).

## Aliases and unique names

A value in braces points at another token: `"$value": "{Colors.Foundation.Blue.500}"`. In Figma the same path reads `Colors/Foundation/Blue/500`; DTA converts between the two when it pulls and pushes.

Aliases carry no collection name, so **variable names must be unique across all collections**. That is what lets DTA resolve `{Colors.Foundation.Blue.500}` wherever it lives, and it is the one rule DTA asks your Figma file to follow.

`dta graph` shows the alias structure, and `dta lint` fails on aliases that point nowhere or in a circle.

## Layers

Most token sets end up with layers, whatever they call them. DTA works with any names, but its checks and defaults speak this model:

| Layer          | Example collection | Modes              | Values                                   |
| -------------- | ------------------ | ------------------ | ---------------------------------------- |
| **Primitives** | `Primitives`       | one                | raw values: `#0057b8`, `8`               |
| **Brand**      | `Brand(Alias)`     | one per brand      | aliases into the primitives              |
| **Dimension**  | `ScreenType`       | one per breakpoint | aliases or values that differ per screen |

`dta analyze` reads a Figma file and suggests which collection plays which role, and `dta init` uses that to propose `collections` and `brands`. The `semantic-must-alias` lint rule keeps a brand layer made of aliases only.

## What the build makes of it

`dta build` writes one set of files for the single-mode collections and one theme per brand:

- **Single-mode collections** (the primitives) become `:root` custom properties in `variables.css` (aliases stay `var()` references) and `base.css` (values resolved).
- **Each brand** listed in `brands` becomes `themes/<brand>.css`, scoped to `[data-brand="<brand>"]`. Switch brands by setting the attribute on any element, `<html data-brand="branda">` for the whole page.
- **JavaScript and Tailwind** files are written next to them.

```css title="output/css/themes/branda.css"
[data-brand="branda"] {
  --colors-brand-primary: var(--colors-foundation-blue-500);
  --colors-brand-primary-dark: var(--colors-foundation-blue-700);
  --colors-brand-accent: var(--colors-foundation-orange-500);
  …
}
```

:::note[Breakpoint modes]
Collections with modes that are not brands (such as `ScreenType` with `Desktop`, `Tablet` and `Mobile`) are read, linted, diffed and pushed, but `dta build` does not write breakpoint CSS for them yet. Their first mode only serves to resolve aliases.
:::

Every file and its format: [Outputs](/reference/outputs/).

## Config

The project config is `dta.config.ts` (also `.mts`, `.js`, `.mjs` or `.json`). Unknown keys are rejected, so a typo shows up as an error instead of being ignored:

```ts title="dta.config.ts"
export default {
  figma: { source: 'file' }, // 'api' on an Enterprise plan
  tokens: { dir: 'tokens' },
  collections: ['Primitives', 'Brand(Alias)', 'ScreenType'], // default: all
  brands: ['BrandA', 'BrandB'],
  outputs: { css: { outDir: 'output/css' }, tailwind: { outDir: 'output/tailwind' } },
  lint: { rules: { 'semantic-must-alias': { severity: 'error', collections: ['Brand(Alias)'] } } },
}
```

Once DTA is installed as a package, `defineConfig` from `design-token-authority` wraps the object for editor completion; it changes nothing else.
