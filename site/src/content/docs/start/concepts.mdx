The few ideas behind every command.

## Token files

DTA follows Figma's variables: a **collection** groups tokens, a **mode** is one set of values (a brand, a theme, a breakpoint). Each collection and mode is one JSON file in the [DTCG](https://tr.designtokens.org/format/) format:

```text
tokens/Primitives.Value.json
tokens/Brand.BrandA.json
tokens/Brand.BrandB.json
```

Format details: [Token files](/reference/token-files/).

## Aliases

A value in braces points at another token: `"$value": "{Colors.Blue.500}"`.

**Token names must be unique across all collections**, because an alias names no collection. It is the one rule DTA asks your Figma file to follow. `dta lint` fails on aliases that point nowhere or in a circle.

## Layers

Call your collections what you like. Most token sets end up with layers like these:

| Layer      | Modes               | Values                     |
| ---------- | ------------------- | -------------------------- |
| Primitives | one                 | raw values: `#0057b8`, `8` |
| Brand      | one per brand       | aliases to primitives      |
| Breakpoint | one per screen size | aliases or values          |

## What the build makes

- **Primitives** become custom properties on `:root`.
- **Each brand** becomes a theme scoped to `[data-brand="…"]`. Switch brands with the attribute: `<html data-brand="branda">`.
- **Breakpoints** become media queries, once you name the collection in `breakpoints`.
- **JavaScript and Tailwind** files come next to the CSS.

Every file: [Outputs](/reference/outputs/).

## Config

`dta.config.ts` (or `.js`, `.json`) says where the tokens are and what to build. `dta init` writes it; unknown keys are an error, so typos don't go unnoticed. `defineConfig` from `design-token-authority` adds editor completion.

```ts title="dta.config.ts"
import { defineConfig } from 'design-token-authority'

export default defineConfig({
  tokens: { dir: 'tokens' },
  brands: ['BrandA', 'BrandB'],
  outputs: { formats: ['css', 'tailwind-v4'] },
})
```
