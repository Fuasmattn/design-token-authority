# Spec: @dta/cli — port every command and prove parity with the legacy CLI

**Status:** ready-for-review
**Part of:** [Token Engine Overhaul](./token-engine-overhaul.md), Epic 6
**Depends on:** `@dta/core`, `@dta/figma`, `@dta/build`, `@dta/lint` (Epics 2–5)
**Related:** ADR 0001, ADR 0002, TICKET-036 (CLI skeleton, snapshot runner), TICKET-039 (parity table, quirk decisions), `test/snapshots/*`

## Problem

The new CLI (`dta-next`) only has the skeleton: config loading, command registration, and "not ported yet" for every command. The packages behind the commands are done and tested, but nothing calls them, so the legacy `src/` cannot be deleted. Six snapshot scenarios (`build`, `lint`, `graph-console`, `graph-dot`, `graph-markdown`, `graph-html`) are on the `PENDING` list, and `pull`, `push`, `analyze`, `clean` and `init` have no snapshot at all.

## Solution

Port the commands one by one onto the packages. The CLI is the only place with side effects: it reads token files from disk, calls the pure package functions, writes files, prints, asks for confirmation and chooses the exit code. Each ported command takes its scenario off `PENDING` (the output must equal the recorded legacy snapshot), or, for commands without a snapshot, gets one recorded from the **legacy** CLI first and then ported against it. At the end the `dta` binary points at the new CLI and 039 deletes the legacy tree.

## Decisions

1. **The CLI is thin.** Parse options → load config → read inputs → call a package → write/print → exit code. Rules, planning, rendering of outputs (CSS, Tailwind, token files) stay in the packages. Report formatting (what a human reads in the terminal) lives in the CLI.
2. **Shared I/O layer first.** One small module reads a tokens directory into `parseTokenFiles` input, writes `{path, content}` files from `buildOutputs`, and turns diagnostics into printed lines. All commands use it; commands do not touch `fs` ad hoc.
3. **Snapshot is the authority.** A command is done when its scenario is off `PENDING` and green. Output that is wrong in legacy (listed in the 039 quirk table) is fixed in the ticket that ports the command, as a reviewed snapshot diff, never silently. Known case: the `build` summary prints `build/js/colorpalette.js` but the file is written to `output/js/`.
4. **Terminal look.** The recorded stdout uses clack's frame (`T`, `|`, `o`, boxes). The new CLI reproduces it with the same library for the commands that have snapshots, so the text matches byte for byte after normalisation. A shared `ui` helper (banner, step, box, summary) keeps this in one place. No new styling work.
5. **Commands without snapshots get one first.** `analyze`, `clean`, `pull --from-file`, `push --dry-run` are recorded from the frozen legacy CLI on fixtures (extending the scenario list in the snapshot runner, reviewed like any other snapshot change) before they are ported. `pull`/`push` against the API use `startFigmaFake` and recordings, never the real Figma.
6. **Config embeds package schemas.** The CLI config's `lint` section becomes `lintConfigSchema` from `@dta/lint` instead of its own copy, so the schema exists once.
7. **Exit codes stay.** 0 ok, 1 command failure, 2 invalid config (as in the skeleton) and, for `lint`, 2 when there are lint errors (the recorded snapshots decide). `--skip-lint`, `--yes`, `--dry-run`, `--format` keep their legacy meaning. `--fix` on `lint` stays "not supported" (spec of `@dta/lint`).
8. **Push safety is unchanged.** The typed confirmation `push variables to figma` stays; `--yes` or `push.skipConfirmation` bypass it. Push never deletes.
9. **Docs HTML (decided: option a).** `build` writes `output/docs/index.html`, generated by the 1.5k-line legacy `formatters/docs-html.ts`. The new CLI may not import legacy code. Options: (a) port that file verbatim, as a function over the model, into a new small package for now (parity first, redesign in Epic 7); (b) keep it out of the new `build` and mark the `build` scenario's docs file as an accepted, reviewed snapshot diff until Epic 7. Recommended: (a), because it keeps the snapshot honest and Epic 7 starts from a tested function.
10. **`test:visual`.** Replaced by Epic 8 (visual-diff). The new CLI keeps the command name registered and says it moved; the legacy implementation is deleted with the legacy tree. Confirmed in 066: no workflow or script calls `dta test:visual`; the root `test:visual` / `test:visual:update` scripts (Playwright) stay until Epic 8.
11. **Cut-over deletes the legacy tree in one PR.** `snapshot:check` re-records from the legacy CLI, so legacy code stays until every command is ported; only then it is deleted together with the recorder's legacy mode.
12. **Cut-over.** After all commands are green: `dta` and `design-token-authority` bins point at the new CLI, `dta-next` is removed, the legacy `sync_*` scripts are dropped from `package.json` (their behaviour is `pull`/`push`), README and CLAUDE.md are updated. Only then 039 removes the legacy tree.
13. **tokenHaus adapter.** Decide keep-or-drop during the `pull` ticket, as recorded in 039 (keep until `--from-file` parity shows nobody needs it).

## Order

Shared I/O layer → `lint` (smallest end-to-end path, proves the pattern) → `build` → `graph` (four formats) → `analyze` + `clean` → `pull` + `push` → `init` (+ `test:visual` decision) → cut-over. Docs HTML (decision 9) is a ticket before `build` if option (a).

## Public API

Unchanged: `runCli`, `loadConfig`, `defineConfig`, types. Commands are internal.

## Out of scope

New commands or flags, `prune`, MCP server, new output targets (iOS/Android), configurable severity for built-in lint rules, redesigning the docs site (Epic 7), visual regression (Epic 8).
