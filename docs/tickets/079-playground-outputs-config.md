## What to build

The playground previews and downloads the build outputs (CSS, Tailwind v4/v3, JS) and generates a `dta.config.ts` plus the `npx dta` commands to continue in a project.

## Acceptance criteria

- [x] Outputs equal what `dta build` writes for the same input (test on the fixtures)
- [x] The generated config is loaded by the real CLI config loader in a test
- [x] Copy and download for every single file (e.g. only `css/themes/branda.css`) and the config, plus one download per output group (CSS, Tailwind, JS) for someone who only needs one kind (maintainer, 2026-10-19)
- [x] "Download all" as one zip with the same folder layout `dta build` writes (plus the generated `dta.config.ts`); the zip library (e.g. fflate) loads with the outputs, not with the page
- [x] Output options a one-time user needs: which outputs (CSS, Tailwind v4, Tailwind v3, JS) and the CSS variable prefix if the config schema has one; the generated config carries the same choices, so the CLI gives the same files
- [x] `@dta/build` and the zip code load lazily (spec decision 9); the page's first-load JS budget from 077 still holds
- [ ] All gates pass plus the site job, and the GitHub run is green (gates and site job pass locally; GitHub run pending, nothing pushed)

## Outcome

- **Choosing outputs needed a config key, so the CLI gets one.** The config schema could not say "only CSS": `dta build` always wrote CSS, both Tailwind versions and JS, and `outputs.tailwind.version` and `outputs.css.prefix` are accepted but unused. For "the generated config carries the same choices, so the CLI gives the same files", `@dta/build` gained `formats` (`BuildOptions.formats`, exported `OUTPUT_FORMATS = ['css', 'tailwind-v4', 'tailwind-v3', 'js']` and `OutputFormat`; each Style Dictionary platform belongs to one format, the others are skipped; default all four), and the config `outputs.formats` (an array of those, at least one; described for the generated reference). `dta build` passes it on; `--verbose` prints the formats it builds. Without the key nothing changes: the 34 CLI snapshots are unchanged. Tests: `build.test.ts` (each format alone, same content as a full build, the same diagnostics, empty list), `commands/build.test.ts` (only the chosen files written and listed, unknown or empty `formats` rejected). Docs: Outputs reference ("Choosing outputs", table of formats → files; "Not built yet" updated).
- **CSS variable prefix: not offered.** The schema has `outputs.css.prefix`, but the build ignores it ("Accepted, not used yet"); a prefix field in the playground would promise files the CLI does not write. Implementing it touches names in CSS, Tailwind v4, `cssBindings` (`dta diff`), `dta audit` and `dta token` — a ticket of its own if wanted.
- **Playground, Outputs tab** (`Playground.tsx`, pure parts in `src/playground/outputs.ts`, heavy parts in `outputs-engine.ts`): Output options (CSS, Tailwind v4, Tailwind v3, JS; all on), "Download all (.zip)"; a status line; the build's diagnostics in the CLI's wording when there are any (a build with errors shows no files, as `dta build` writes none); Output files grouped CSS · Tailwind · JS with a zip per group and Copy, Download and a preview per file; "Take it to the CLI" with the generated `dta.config.ts` (preview, Copy, Download) and the steps. Brands are the ones the structure analysis suggests (`suggestedBrands`), the output folders the defaults. A file's preview opens in the DetailPanel (side panel from 1024 px, bottom sheet below) with kicker `Output · CSS · 746 B`, Copy and Download, and the file's text.
- **Lazy loading** (spec decision 9). `outputs-engine.ts` (`buildFiles` → `buildOutputs`, `zipFiles` → fflate `zipSync`) is imported dynamically the first time the Outputs view opens (also through the summary or `#outputs`); after that new reads are built in the background so the summary keeps its count. fflate 0.8.2 is a site dev dependency. **First load of /playground:** 7 files, 185 KB minified, **54.0 KB gzip** (115: 49.9 KB; budget 60 KB holds; +0.9 KB is Vite's preload helper for the dynamic import, the rest the new components and outputs.ts). **Lazy chunk** `outputs-engine-*.js`: 2.16 MB minified, **600 KB gzip** (Style Dictionary + `@dta/build` + fflate, one chunk). The e2e test checks the page's first scripts include neither Style Dictionary nor the engine.
- **Summary line:** decided for the "build outputs" affordance plus the count: the last part reads `build outputs` until the files are built (a button to the Outputs tab, which builds), then `11 output files`; the tab reads `Outputs · 11`, as on the board. The count follows the chosen formats (`7 output files` without CSS).
- **Generated config:** `figma: { source: 'file' }`, `tokens: { dir: 'tokens' }`, `brands` (when found), `outputs.formats`, and a first comment line with the command. While `NPM_RELEASED` is false (landing content) it is a plain `export default { … }` without the `defineConfig` import, which a project cannot resolve before the release (the Quick start says the same); with `NPM_RELEASED` it imports `defineConfig` from `design-token-authority` (tested with a stub package).
- **Commands:** `npx design-token-authority build`, and for a plugin export first `npx design-token-authority pull --from-file <file>` (the dropped file's name, `export.json` for a paste); never `npx dta` (test). Below the steps, while `NPM_RELEASED` is false: "DTA is not on npm yet (TICKET-090), so npx cannot find it until the first release … run it from a clone, as the Quick start shows."
- **Downloads:** blob URLs made in the page (nothing is uploaded). A single file downloads under its base name (`branda.css`; two `tailwind.css` from different folders get the browser's usual suffix — the group zip keeps the folders); groups as `dta-css.zip`, `dta-tailwind.zip`, `dta-js.zip`; everything as `dta-outputs.zip` with each file at the path `dta build` writes plus `dta.config.ts` at the root. Token files are not added to the zip (the spec says outputs plus config); the steps say where they go. A download clicked while building waits for the build.
- **Tests.** `src/playground/outputs.test.ts` (Node): for brand-ab with all formats, `['tailwind-v3','js']`, `['css']`, and daisyui, the playground's files equal byte for byte what the real CLI (`runCli(['build'])`) writes in a temp project with the fixture's token files and the generated config, which the real `loadConfig` loads with the same formats; brand-ab also equals the reference snapshot `test/snapshots/brand-ab/build/files`; a tokenHaus export equals `pull --from-file` + `build` run with the playground's own steps; the zip unzips to the CLI's tree plus the config; grouping, sizes, the choice list equals `OUTPUT_FORMATS`. `playground.e2e.test.ts` (Chromium): nothing requested before the Outputs view opens; after it only same-origin `/_astro/*.js` chunks (one of them with Style Dictionary), then no further request; blob: downloads and the favicon ignored, with the reason; files equal the snapshot; preview shows the whole file; Copy puts the file on the clipboard and shows "Copied"; single file, CSS zip, Download all (folders + config) and the config download checked by content; unchecking CSS gives 7 files and a config and zip without CSS; layout shift 0 while the outputs build (390 light, 1280 dark) and nothing wider than the screen with the Outputs view, a file preview and the config preview open. `contrast.e2e.test.ts` audits three more playground states at AAA (Outputs, output file open, config open with a file copied) × Light/Graphite × 1280/390, and the new stories.
- **Design system.** New Preact components with a `.css`, docs page and stories at 1280 and 390: `OutputOptions` (named checkbox group + actions; two columns and a full-width action below 560 px), `OutputFiles` (groups, file rows, `aria-current` row tint; path on its own line below 560 px), `CopyButton` (the Button, "Copied" with the pass dot at a fixed width, polite live region), `CliHandoff` (config row, numbered steps with command chips, note). Changed: `Button` gained the `quiet` variant (hairline, no fill: the small action repeated on rows; docs and story updated), `CommandButton`'s styles moved to a shared `CommandButton.css` with prefixed classes so the island renders the same chip (landing markup unchanged otherwise; long commands may wrap inside the hand-off), `DetailPanel` gained `actions` and `code` (a file's text, wrapped with indentation kept, scrolling inside) and breaks path titles after each `/` (stories `file`, `file-sheet`), `SummaryLine`'s story and docs show the output count. The overview page gained a "Files to take away" pattern and the four components in its playground list. Sidebar order 24–27.
- **Website docs:** the Start page, the Token files reference and the Outputs reference mention the playground's outputs and downloads; the playground page's intro and description too.
- **Decisions taken (closest to the spec and the boards):**
  - Groups, options and the hand-off are rules and type on the canvas (as 115 kept Structure and Lint), not the boards' white cards; the hand-off is not the board's dark strip but a section whose commands are the site's terminal-coloured command chips (no inverse button variant needed).
  - On phones the options stay visible (two columns) instead of behind an "Options" disclosure, the groups stay open, and there is no fixed CLI bar at the bottom (it would compete with the bottom sheet); every row keeps Copy and Download.
  - The JS group also downloads as a zip (`Download JS (.zip)`), as on the desktop board, so every group works the same way.
  - Long lines in a preview wrap rather than scroll sideways (a sheet on a phone should not scroll in two directions); Copy and Download give the exact text.
- **Gates:** prettier, typecheck, boundaries, `pnpm test` (933 passed, 60 browser tests skipped), snapshot check (34, unchanged), `pnpm site:build` (111 pages, links valid) and `test:contrast` with Chromium (63 passed). Node 24.14.1. GitHub run: pending, nothing committed or pushed.
- **Left open:** the CSS prefix (above); `dta init` still asks "which outputs" and writes `outputs.css`/`outputs.tailwind` keys that only move folders — it could write `outputs.formats` now (separate ticket); choosing brands or output folders in the playground is not offered (one-time use takes the found brands and the defaults).
