# TICKET-115: Playground workspace layout: source bar, summary, tabs, detail panel

**Phase:** 8 — Token Engine Overhaul, Epic 7b (playground)
**Priority:** High
**Effort:** M
**Blocked by:** 077
**Status:** done (2026-10-19), pending the GitHub run
**Spec:** [playground](../specs/playground.md) (decision 15); reference boards in `docs/specs/playground/prototypes/` (approved by the maintainer 2026-10-19)

## Problem

077 stacks input, structure and lint on one page. With the graph (078) and outputs (079) added, the page gets long and scrolling loses context, worst on phones. The input is only needed until something is loaded.

## What to build

The playground as a workspace (spec decision 15), in place before 079 adds the outputs:

- **Before loading:** the drop area (also the file-picker button) takes the page; "Load example"; "Paste JSON instead" opens the paste field (no longer side by side with the drop area).
- **After loading:** a one-line **source bar** (what is loaded, file count, "Replace files", "Paste JSON instead"); a **summary line** that stays visible (collections, brands, breakpoints, tokens, findings; each part a button that opens its tab); **tabs** Structure · Lint · Graph · Outputs (Graph and Outputs show a short "coming" state until 078/079; the Outputs tab must not load `@dta/build` yet). On phones the tabs are a sticky bar under the summary.
- **Detail panel:** desktop: a side panel next to the view (structure row → the collection's tokens with alias chains and resolved values for the selected mode; lint line → the full message); phones: the same content in a bottom sheet. Closable, keyboard reachable, focus returns to the row that opened it; Escape closes it.
- **Lint grouped by rule** with counts; a group opens to its lines.

Design-system first: `SourceBar`, `SummaryLine`, `Tabs` and `DetailPanel` (side panel / bottom sheet as one component) as components with docs pages and stories (desktop and phone width); `TokenInput`, `StructureTable` and `Findings` from 077 are reused or adjusted, not duplicated. Native `<dialog>` for the phone sheet if it fits the a11y requirements.

## Outcome

- **Workspace** (`site/src/playground/Playground.tsx`). Before loading: the page intro and `TokenInput`, whose drop area now takes the page (about 40 % of the screen, at least 220 px) with one action row under it: "Load example" (and what it is) and, at the end, "Paste JSON instead", which swaps the drop area for the paste field ("Choose files instead" swaps back; focus follows). After loading: the intro stays for screen readers only (`.playground:has(.pg[data-loaded])`), then `SourceBar`, the paste field under it on request, `SummaryLine`, and `Tabs` Structure · Lint · Graph · Outputs. Invalid input shows the source bar and the CLI's diagnostics (077's `Findings` "Input"), no summary and no tabs. Graph and Outputs show one line each ("comes next (TICKET-078/079)"); Outputs imports nothing, so `@dta/build` stays out (the JS test still checks there is no Style Dictionary in the page's scripts).
- **Tabs and the hash.** WAI-ARIA tabs with automatic activation: ←/→ (wrapping), Home, End; roving `tabindex`; one `tabpanel` labelled by the selected tab. Selecting writes `#structure`/`#lint`/`#graph`/`#outputs` with `history.replaceState`; the hash is read on load and on `hashchange`, so a reload or shared link opens that view once something is loaded (other hashes, such as the skip link's `#main`, are ignored). Each summary part is a button that selects its tab and moves focus to it. Below 560 px of container width the tabs share the row and the bar is sticky at the top of the screen.
- **Detail panel** (`DetailPanel`, one native `<dialog>`): from 1024 px shown non-modal (`show()`) next to the view in a two-column grid (`.pg-work`, panel up to 400 px), sticky; below, modal (`showModal()`) as a bottom sheet (fixed, 85 dvh at most, grab handle, top corners rounded). Crossing 1024 px while open switches the presentation. Opening moves focus to the panel's title; ×, Escape (the dialog's `cancel` for the sheet, a document listener for the side panel) and a tap on the sheet's backdrop close it and return focus to the opener synchronously (closing from the page, e.g. a tab change, goes through the same path in an effect). Structure rows (the collection name is a button, its hit area the whole row) open the collection: modes as a switch (`aria-pressed`), `N tokens, M aliases in <mode>.`, and every token with its alias chain and resolved value in the selected mode, a swatch for colours. Lint lines open the finding: kicker `error · rule`, the token (or the file), the whole CLI line, and the token's chain in the finding's mode. The opener row is marked `aria-current`.
- **Resolution** (`analyse.ts`): `collectionDetail(model, collection, mode)` and `findingChain(model, tokenPath)` call `resolve` from `@dta/core` with the collection's mode selected (aliases read like Figma); a chain that does not resolve shows `resolve`'s message. `PlaygroundResult` now keeps the `model`, the breakpoints (modes of the dimension collection), the token count, and the lint by rule.
- **Lint by rule, wording from `@dta/lint`.** `report.ts` gained `BUILT_IN_RULES` (the three rules `lintTokens` runs without a config), `groupViolationsByRule` (built-in rules first, also when clean, then others in the order found), `formatRuleCount` (`1 error, 2 warnings` / `no findings`) and `LINT_MESSAGES.noFindings`; tests in `report.test.ts` (including that every rule a config-less `lintTokens` reports is listed). The Lint view shows `formatLintSummary` + verdict, a note, and one row per rule with its count; a rule with findings is a native disclosure that opens to its lines; the summary line uses `lintCounts` (`0 lint findings` when clean). CLI output unchanged (34 snapshots).
- **Design system.** New Preact components with a `.css` each, docs page (when to use, guidelines, tokens used) and stories: `SourceBar` (example; plugin export with the paste field open), `SummaryLine` (default), `Tabs` (Structure; Lint with count, sticky), `DetailPanel` (side; sheet at 390). Adjusted, not duplicated: `TokenInput` (drop area takes the page, paste toggle; exports `PasteForm` and `readFiles`, used by the source bar; the `loaded` prop moved to `SourceBar`; story `loaded` → `paste`), `StructureTable` (`onSelect`, `selected`, `hideCaption`; story `selectable`), `Findings` (rule groups with `count`/`severity`, `note`, selectable lines with a file `detail`; story `rules`, on a small set with a dangling alias and a default mode name, `src/examples/problem-files.ts`). `button.mdx` documents `Button.css` for islands; the design-system overview gained a Patterns section (severity markers, the workspace, side panel / bottom sheet) and a playground group in its component list; the playground components are ordered 17–23 in the sidebar in the order a visitor meets them. WorkflowRail's page already matched its component; no change.
- **Tests.** `playground.e2e.test.ts`: the whole flow (paste toggle before loading; example → source bar status, summary parts, structure, summary → Lint; "Replace files" with a multi-file chooser; a pasted plugin export → `1 error found. Lint failed.`, rule row `1 error`, the line opens the panel with the CLI line; invalid JSON → the CLI diagnostic, no tabs) with **no request after load** (Chromium re-reads the cached favicon when the hash changes; the test ignores `/favicon.svg` and says why) and no page errors; tabs by keyboard (arrows, Home, End, wrap) with the hash, and a reload on `#graph`; the panel at 1280 (non-modal) and 390 (`:modal`): opened by keyboard, focus on its title, mode switch changes the values, Escape and × return focus to the row; layout shift 0 on load and nothing wider than the screen at 390 and 1280 in both themes for empty, paste field, loaded, panel open, Lint and invalid; the sticky tab bar on a phone; the JS budget. `contrast.e2e.test.ts` audits the playground at AAA in six states (empty, paste field, example, panel open, lint finding open, invalid input) × Light/Graphite × 1280/390, plus every story. `analyse.test.ts` covers the new result shape, `collectionDetail` per mode and `findingChain` (resolved and dangling).
- **JS of the playground page:** 6 files, 173 KB minified, **49.9 KB gzip** (077: 45.5 KB); the island chunk 155 KB / 41.6 KB gzip. Budget 60 KB gzip holds; no Style Dictionary.
- **Decisions taken (closest to the spec and the boards):**
  - The page's `h1` and intro stay in the DOM after loading, visually hidden, so the page keeps its heading; the boards show none once loaded.
  - The bottom sheet's backdrop is the canvas at 80 % (`bg-canvas` with opacity), not a dark scrim: the tokens have no scrim colour, and a canvas veil works in both themes without adding one.
  - Structure and Lint stay rules and type on the canvas (077's design-system rule "no card"), not the boards' white cards; the source bar is the one surface strip, as on the boards.
  - The Lint view lists the three built-in rules (what a visitor without a config gets), not the board's seven: the configurable rules do not run without `dta.config.ts`, and listing them as "0 findings" would claim they ran. Rule groups start closed (summaries first).
  - The tab label carries the finding count (`Lint · 1`), as on the boards; the summary's output-file count waits for 079.
  - "Replace files" opens the file picker directly; dropping files onto the workspace is not supported once something is loaded (the drop area is the empty state).
  - The Graph and Outputs placeholders name their tickets in one line each, as the board does for the graph.
  - A finding about a file (no token path) shows the file as its title and no chain; a pair (`color-contrast`) shows no chain either.
