# TICKET-116: Motion tokens, a motion rule against change blindness, and playground transitions

**Phase:** 8 — Token Engine Overhaul, Epic 7b (playground) and the design system
**Priority:** High
**Effort:** M
**Blocked by:** 079 (same files; start after it lands)
**Status:** done (pending the GitHub run)
**Spec:** [playground](../specs/playground.md) (decision 15); design system principle 7 ("Deterministic motion")

## Problem

The playground changes state abruptly: the drop area is replaced by the source bar, tabs swap content, the panel or sheet appears, lint groups open, counts change. When something changes without motion, people miss what changed (change blindness), and the page feels jumpy. The maintainer wants transitions on the playground and a common rule for the whole design system (2026-10-19).

The design system has no motion tokens: components use ad-hoc literals (`0.15s ease`, `0.2s ease`, `0.35s cubic-bezier(0.2, 0.8, 0.2, 1)`, `0.6s …`, `cubic-bezier(0.4, 0, 0.2, 1)`), which the "token variables only" rule should not allow.

## What to build

1. **Motion tokens in `site/tokens`**, built with `dta build` like the rest: a short duration scale (e.g. `motion.duration.instant | fast | base | slow`, roughly 0 / 120 / 200 / 320 ms) and two or three easings (`motion.ease.standard` for moves, `enter` for things appearing, `exit` for things leaving). Check how DTA's own build emits them first: durations must come out with `ms` and easings as `cubic-bezier(…)` strings. If the build cannot express that correctly today, the fix goes into `@dta/build` (with a CLI snapshot change recorded by name) or the tokens use a type the build already handles correctly; record the choice.
2. **A motion rule in the design system** (rewrite principle 7 and add a "Motion" page under `design-system/`): every state change a person should notice is transitioned, never instant: things that appear grow or fade in from where they come from, things that leave go back there, content that changes in place crossfades, a value that changes is briefly highlighted (`action.subtle`), and layout shifts animate instead of jumping. Motion stays short and functional (no bounce, no decoration beyond the landing page's well). `prefers-reduced-motion`: positions do not move; changes become instant or a short crossfade, and the highlight of changed values stays (it is information, not motion). Include do/don't examples and the token table.
3. **Apply it to the playground** (all states from 077, 115, 079):
   - input → workspace: the drop area collapses into the source bar (View Transitions API where supported via `document.startViewTransition`, a plain crossfade otherwise); results appear with a short staggered fade, not all at once
   - tab change: the panel content crossfades; the tab indicator moves to the new tab
   - side panel slides in from the right, bottom sheet from the bottom, both back on close; the backdrop fades
   - lint groups and other disclosures animate their height (`interpolate-size` / grid-rows trick, no JS measuring if avoidable)
   - selected rows, the summary counts and the Lint tab count highlight briefly when they change (e.g. after "Replace files")
   - errors for invalid input fade in where they appear
4. **Use the tokens everywhere:** replace the literal durations and easings in `site/src/components/ds` with the motion tokens (the well's long orbit periods stay their own `well-*` values); extend `components.test.ts` so a new literal duration or easing in a component fails.

## Outcome

- **Tokens** (`site/tokens/Primitives.Value.json`, group `motion`, built with `dta build`): `motion.duration.instant | fast | base | slow` = `0ms | 120ms | 200ms | 320ms`, plus `motion.duration.highlight` = `1200ms` (how long a changed value stays lit) and `motion.stagger` = `40ms` (between items that appear one after another); `motion.ease.standard` = `cubic-bezier(0.2, 0, 0, 1)`, `enter` = `cubic-bezier(0, 0, 0, 1)`, `exit` = `cubic-bezier(0.3, 0, 1, 1)`. CSS out of `dta build`: `--motion-duration-base: 200ms;`, `--motion-ease-standard: cubic-bezier(0.2, 0, 0, 1);` (in `base.css`/`variables.css`, Tailwind v4 and JS likewise). `tokens.test.ts` checks the values and the built CSS (`\d+ms`, `cubic-bezier(…)`).
- **Type choice (recorded):** `string` tokens, which the build already writes as they are; **no change to `@dta/build`, no CLI snapshot change** (34 unchanged). DTCG `duration`/`cubicBezier` were not an option without a larger change: `@dta/core` reads only the four Figma types (`color`, `number`, `string`, `boolean`) and reports other types as `unsupported-type`, leaving them out of the model (so out of the build); a `number` duration comes out unitless (only Figma pixel scopes get `px`). Figma has string variables, so the tokens still round-trip. Adding DTCG types to the token model would be its own ticket. Figma scopes are empty (hidden from Figma's pickers).
- **Generated:** `pnpm report:tokens` re-ran, so the `dta diff` report's token CSS (`packages/visual-diff/src/report/tokens-css.ts`) now carries the motion variables too (generated, no snapshot change).
- **Design system docs:** principle 7 rewritten ("Motion against change blindness"); new page **Design system → Motion** (`design-system/motion.mdx`: the rule, reduced motion, do/don't table, the token table, how it is built), linked from the overview and the sidebar (right under "DTA Drafting Table"); new token page **Tokens → Motion** (`tokens/motion.mdx`, durations as bars, easings as curves, from `MotionTokens.astro` reading the token files through `motionTokens()` in `src/lib/design-tokens.ts`). Every touched component's docs page has a Motion note (Tabs, Detail panel, Findings, Summary line, Source bar, Token input, Output files, CLI hand-off, Structure table, Card, Redline, Logo, Nav, Token cycle); "Tokens used" lists update themselves.
- **New in the design system:** `Changed` (`Changed.tsx` + `.css`, docs page, story `changed--highlighted` held at its highlight): a short value that lights up in `action-subtle` / `action-text` (held for the first 35 % of `highlight`, then fading on `exit`) whenever it changes after the first render; padding taken back by a negative margin, so nothing moves; it stays under reduced motion (it re-declares its animation `!important` against the frame's reduced-motion rule). `src/components/ds/motion.ts` (not a component): `transition(update, type)` (View Transition with types where available, callback form for older Chromium, otherwise and under reduced motion the update at once) and `useChanged`/`countChange`; tested in `motion.test.ts`.
- **Frame** (`src/styles/site.css`, section "Motion"): `dta-appear` (fade in from `space-2` below), View Transition timing — a read (`dta-read`) crossfades the root on one curve while named parts move (`slow`, `standard`) and new parts arrive after `base`; a change in place (`dta-tabs`, `dta-outputs`) keeps the page live and crossfades only parts of `view-transition-class: dta-swap`; parts that change size are clipped and keep their size (`object-fit: none`), the source morph centred. The reduced-motion rule now also covers `::backdrop` and the View Transition pseudo-elements.
- **Playground** (all on the tokens):
  - input → workspace: `read()` runs inside `transition(…, 'dta-read')`; the drop area (or the paste field) and the source bar share `view-transition-name: dta-source`, so the input collapses into the bar; summary and tabs fade in after it (VT `only-child` delay plus `.pg[data-loaded] > *` staggered by `motion.stagger`). Errors of an invalid input, the paste field under the bar and later arrivals fade in the same way. Without the View Transitions API: the stagger alone.
  - tabs: one measured indicator (`--dta-tab-x/y/w/h`, ResizeObserver) moves over `base`; the tab's own outline stays the no-script look (stories unchanged). Tab changes (also from the summary line) are View Transitions of type `dta-tabs`: only the panel crossfades and its box eases to the new height.
  - side panel / sheet: CSS only on the native `<dialog>` (`@starting-style`, `transition-behavior: allow-discrete` on `display` and `overlay`): side panel from the right (`space-6` + fade), sheet up from the bottom, backdrop fades; both leave the same way with their last content (the page keeps it while closing). The view column opens with the panel (`grid-template-columns` + `column-gap` transition, panel kept at 400 px so it slides in from the edge instead of squeezing); on close the panel fades first, then the column closes (`fast` delay, `base`). `DetailPanel` gained `data-static` (stories), and the sheet is positioned by `data-presentation` instead of `:modal`, so it stays fixed while it slides away.
  - lint groups: `::details-content` block-size with `interpolate-size: allow-keywords` (no JS); chevron turns over `base`.
  - highlights: each summary part and each tab count is wrapped in `Changed` (summary keys are now positional, so a part persists and its change is seen): after "Replace files", toggling formats (`11 output files` → `7 output files`, `Outputs · 11` → `· 7`) and when outputs first build (`build outputs` → `11 output files`). Selected rows (structure, findings, output files) tint over `fast`.
  - output list: while other formats build, the files of the same read stay on screen; the new build lands inside `transition(…, 'dta-outputs')`: groups (named after their heading ids) that stay move, removed ones fade, the CLI hand-off moves. The first build of a read is not animated (it appears where the status was; animating it delayed the change past the 500 ms input window and counted as layout shift).
- **No literals:** every duration/easing in `src/components/ds` is a token (Nav, Logo, Card, Redline, TokenCycle, TokenInput, Findings, plus the new rules). The timings were mapped to the scale rather than reproduced (e.g. the redline draws over `slow` after `base` instead of 800 ms after 300 ms; the nav sheet opens over `slow`). `components.test.ts` fails on a literal duration (`\d(ms|s)`) or easing (`ease*`, `linear`, `steps()`, `cubic-bezier()`) in a `transition*`/`animation*` declaration of any component; endless loops (`infinite`: the well's orbits, the floating objects, the terminal cursor) keep their own periods, as the ticket allows.
- **Tests** (`motion.e2e.test.ts`, in the site job's `test:contrast`): the playground flow (load, tab change, panel/sheet open and close, Outputs, uncheck CSS, paste an export, open a rule) at 1280 and 390 px — under reduced motion only `background-color`/`color` of `dta-changed` animate, no View Transition starts, the panel is in place on its first frame, the rule opens at once, `7 output files` and the tab's `7` are highlighted on the `action-subtle` ground, layout shift 0; with motion: ≥3 View Transitions, the panel and tab indicator move, the backdrop (phone) or the column (desktop) animate, the rule's height grows, every duration and delay is a token (or a sum of two), the highlight shows, layout shift 0. The landing page: layout shift 0 while scrolling and no horizontal scroll at 390 and 1280, with and without reduced motion. `contrast.e2e.test.ts`: new playground state "changed counts highlighted" (highlights paused at their start) at AAA in Light and Graphite at 1280 and 390. Existing checks unchanged and passing (no horizontal scroll at 390, layout shift 0 per state, no request after load).
- **JS of the playground page:** 7 files, 187 KB minified, **54.7 KB gzip** (079: 54.0 KB; budget 60 KB holds); lazy `outputs-engine` 2.16 MB / 600 KB gzip, unchanged.
- **Visual check:** frames at 10 % playback speed (CDP `Animation.setPlaybackRate`) of input → workspace, tab change, side panel open/close, output formats toggled (1280) and the bottom sheet (390), and a WebM of the whole flow at 1280. Adjusted after looking: the root crossfade runs old and new on one curve (different curves washed out the unchanged header), new parts wait until the moves are mostly done (the summary overlapped the collapsing bar), a tab change no longer fades the whole page (only `dta-swap` parts crossfade), the side panel keeps its width while its column animates (it squeezed to one character per line on close).
- **Decisions taken (closest to the ticket and spec):**
  - Two extra tokens, `motion.duration.highlight` and `motion.stagger`: the highlight must outlast `slow` to be noticed, and a stagger needs a step; both are part of the rule, so they are tokens, not literals.
  - Under reduced motion changes are instant (the ticket allows instant or a short crossfade); View Transitions are not started at all.
  - Shared motion CSS (keyframes, View Transition timing, reduced motion) lives in the frame `site.css`, because pseudo-elements of View Transitions are page-wide; components carry their own transitions. Stories still render with motion off.
  - Selected rows tint over `fast` rather than flashing: the selection itself stays visible, a brief highlight would add nothing.

- **Left open:** browsers without `::details-content` (Firefox, Safari at the time of writing) open lint groups at once and those without View Transitions get the stagger and CSS transitions only; DTCG `duration`/`cubicBezier` in the token model (and building them) would be a separate ticket.
