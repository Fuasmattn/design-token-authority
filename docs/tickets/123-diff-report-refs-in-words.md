# TICKET-123: `dta diff` report: refs in words, commit hashes for both sides

**Phase:** 8 — Token Engine Overhaul, Epic 8 (`dta diff`)
**Priority:** Low
**Effort:** S
**Blocked by:** 109
**Status:** done

## Why

Maintainer feedback on 109 (2026-10-21): the story row's headings now read "With this change" / "Before this change", but the token table still says `base` / `head` (git words), and only the base side names a commit. The "with this change" side says "working tree", because `result.json` records nothing about the head.

## What to build

1. **Token table in words:** the columns (and the phone list's row labels) read "Before" and "With this change" instead of `base` / `head`; the same wording everywhere in the report (alt texts, story notes, summary markdown if it uses the words, and the GitHub comment from `actions/lib/dta-diff.mjs` if it does).
2. **Commit hash under each side:** the table's column heads (and the panel headings' meta) show the ref and short commit hash below the words, e.g. "Before" / `main · 2ee9b31` and "With this change" / `feature/x · 9f3c1a2`.
3. **Record the head in the result:** `result.json` gains an optional `head` (ref name if on a branch, commit sha, and whether the working tree had uncommitted changes), written by `dta diff`; the schema (`dta.diff/1`) stays readable for older results (field optional; a report without it falls back to "working tree"). Uncommitted changes show as e.g. `feature/x · 9f3c1a2 + uncommitted changes`. Documented in the result schema/reference and the "Reading the report" guide.

4. **Notes never cover the story (maintainer, 2026-10-21, after the 123 screenshots).** At 390 the token notes under the light panel's button covered the graphite panel's text below it (also in the report pushed with 109). Rule: a note sits on the image only where it covers nothing but background; otherwise the outline gets a small numbered marker (1, 2, …, ink-lined like the outline) and the full notes are listed right under the image with the same numbers. Works for several outlined elements; the "Show before" toggle hides markers like outlines, keeping their space.

5. **Markers and grouped notes (maintainer, 2026-10-21, after the 123b screenshots).** (a) A numbered marker never covers story content either: it sits on the outline's outer edge where the flat-surface check allows (same rule as notes), otherwise outside the outline next to it. (b) Boxes explained by the same set of token changes share one list entry ("1, 2 · Colors.Brand.Primary … · Radius.Card …"); this is common, since stories render the same component in light and dark side by side.

**Item 4: notes never cover the story (2026-10-21).**

- **Rule:** a note (the label, not its leader) sits on the image only where every cell of the screenshot under it is flat and of one colour, or below the image (the stage's paper). Otherwise its box gets a numbered marker (1, 2, … in reading order, top to bottom then left to right) on the outline's top left corner and its notes are listed right under the image with that number, one box per line, in the notes' own style. Works per box, so a row can keep some notes on the image and list others; markers and notes never overlap (markers count as obstacles). Leaders are not checked: a 2 px line may cross an edge.
- **"Flat", deterministic:** `dta diff` reads each shown row's "after" PNG back when it writes `index.html` (`renderReportHtml(result, { image })`, new optional argument) and computes a flat map of the cropped canvas (`report/flat.ts`): 4 × 4 px cells, a cell is flat when all its pixels are opaque and within 6 per channel of its first pixel, flat cells of nearly the same colour share a letter; run-length encoded in `data-flat` on the row's canvas (a page of paper is a few characters). The decision needs the reader's width (notes are larger relative to a scaled screenshot on a phone), so the report's script makes it: it lays the notes out as before, keys the boxes whose notes are not clear, lays out the rest again, until stable (bounded). No map (a report rendered from `result.json` alone, an unreadable image): every box is keyed, "when in doubt". No schema change. The Orbit run: at 1280 and 390 both buttons' notes would cover the panel's edge or the graphite panel, so both are keyed and listed.
- **Markers:** signal with a 1 px `ink-900` line (like the outline; the contrast suite's edge check covers markers and list keys at 3:1), the number in `signal-fg` (redline label exception), `radius-full`. In the marks layer, so "Show before" hides them with the outlines; the list is in the notes layer, hidden the same way; both keep their space (layout shift 0). Without JavaScript nothing changes: notes line up under the image, no markers.
- **DiffCard:** same script logic; new prop `surfaces` (flat boxes in canvas pixels, one entry per surface) turned into the same map at build; without it every note is listed. Stories get the stand-in's surfaces (paper around the card, the card's navy right of the title); new story `diff-card--listed` (two cards 64 px apart: at 1280 the card's note fits in the gap and the button's notes are listed, at 390 both are listed), 1280 and 390. The unexplained story now lists its note (it fits neither beside the title nor under it).

- **Tests:** `flat.test.ts` (flat cells by colour, antialiasing within tolerance, crop, run length). `html.test.ts`: the map of the shown image (cropped rows) when the image can be read, none without or for an unreadable image; marker and key markup (`data-i`), CSS (hidden until keyed, hidden with "Show before"). **Item 5: markers and grouped list entries (2026-10-21).**

- **(a) Marker placement** (`report/placement.ts`, `PLACEMENT_JS`: plain browser JavaScript the report's script includes verbatim and the tests evaluate): a marker takes the first spot that covers one flat colour (the notes' flat map, same check) and crosses nothing placed. Order: next to the outline's outer edge (3 px box offset + 2 px outline + ink line = 6 px, then 2 px gap), outside the box: above at the left corner, middle and right corner; right (top, middle, bottom); below; left; the four diagonal corners. Then farther out, 4 px at a time up to 48 px, along the top, right, bottom and left sides. Always inside the canvas. Obstacles: every outline as a ring (a marker inside a larger outlined box, next to a nested element, does not cross it; one overlapping its band does), notes on the image, markers already placed (reading order). Notes in turn avoid markers and outline rings; the loop that keys boxes re-places markers each round, so the result is stable and deterministic. Only if no flat spot exists within 48 px does the marker take the first edge spot (`covers`; also when the row has no flat map). Markers moved out of the outline elements into the marks layer (`.marks > .key[data-i]`), placed by the script; still hidden with "Show before".
- **(b) Grouping:** each box carries its set of token changes (`data-set`: token ids, sorted; "unexplained" for an unexplained box). Keyed boxes with the same set share one list entry, its key "1, 3" and the notes once (`groupKeys`); others keep their own; markers keep their own numbers. The Orbit run now lists "1, 2 · Colors.Brand.Primary … · Radius.Card …" once for the light and the dark button.
