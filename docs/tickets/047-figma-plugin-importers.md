# TICKET-047: Figma: documented input format, schema and adapters

**Phase:** 8 — Token Engine Overhaul, Epic 3 (@dta/figma)
**Priority:** Medium
**Effort:** M
**Blocked by:** TICKET-040
**Status:** ready-for-agent
**Spec:** [figma-package](../specs/figma-package.md) (decision 11)

## What to build

Make "where do I get the file without the Enterprise API" a user-land concern: DTA documents and validates its own input format, publishes a schema for it, and keeps third-party export formats in small removable adapters.

## Acceptance Criteria

- [ ] A Zod schema for the one-file-per-mode DTCG file (tokens, groups, `$type`/`$value`, `$description`, `com.figma` extensions); a JSON Schema generated from it is committed (or generated by a script and checked in CI); both fixtures validate
- [ ] Docs page (in `docs/`) describing the format and listing ways to obtain it (Enterprise REST API, a plugin of the user's choice plus conversion, Figma's native export when available) as guidance, without endorsing or depending on one plugin; CLAUDE.md's "compatible plugins" list is reworded accordingly
- [ ] `importPluginExport(json)` returns `{ format, model, diagnostics }` for adapters registered in one place; input is validated with Zod at the entry, a wrong shape yields a diagnostic naming the failing path, never an exception
- [ ] The tokenHaus adapter (legacy `importers/tokenhaus.ts` and `detect.ts` behaviour, including `detectFormat`) is ported as one isolated adapter file with its legacy test cases re-expressed through the public API; removing it requires touching nothing else
- [ ] Unknown formats produce a diagnostic that points to the format documentation
- [ ] 039 parity table: importers and `pull --from-file` rows updated, including the keep-or-drop decision for the tokenHaus adapter
- [ ] All gates pass, and the GitHub run is green
